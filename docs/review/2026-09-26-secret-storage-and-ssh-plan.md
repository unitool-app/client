# Отчёт: защита секретов на платформах и план SSH-ключей

**Дата:** 2026-09-26 · **Что смотрели:** `.ai-notes/done/ios/01-ios-support.md`, `services/vault`
(Android, iOS), `apps/twofa/AccountStore`, правила бэкапа Android, `.ai-notes/done/ssh-new/01–04`.
**Результат:** оценка ниже и заметка `.ai-notes/done/ssh-new/05-tiers-passphrase-ios.md` (D162–D172,
вопросы 81–84, 86–87). Код не менялся.

## 1. Вопрос

Действительно ли секреты (аккаунты 2FA) шифруются «на чипе» на всех платформах, и можно ли
быть уверенными, что это работает. Закрывает ли план SSH-ключей те места, где уверенности нет.

## 2. Вердикт

Да, это может быть безопасно, с двумя честными оговорками.

1. Там, где чипа нет, защита равна силе пароля ssh-ключа и ничему больше.
2. Ни один уровень не защищает от кода, который уже работает внутри процесса или с root, в тот
   момент, когда человек сам подтвердил операцию. Это предел любого ssh-агента, а не дефект
   плана.

## 3. Что реализовано и что из этого проверено

| Платформа | Что есть | Проверено |
|---|---|---|
| Android | `AndroidKeystoreVault`: AES-256-GCM, ключ создаётся в `AndroidKeyStore` и не покидает его. Файл хранилища исключён из бэкапов. | Инструментальный тест на реальном Keystore есть, но идёт только с подключённого устройства. CI его не запускает. |
| iOS | `IosKeychainVault`: P-256 в Secure Enclave, ECIES, класс `WhenUnlockedThisDeviceOnly`. Блоб в `NSUserDefaults` попадает в iCloud-бэкап, но без ключа бесполезен: на новом устройстве даст «Unreadable», не утечку. | **Ни разу не выполнялся.** Компилируется под iOS, тестов нет, Mac не было. |
| Desktop, web | Сейф не регистрируется. Аккаунты 2FA лежат открытым JSON. | Задокументировано в `AccountStore`, пользователю не показано. |
| Поведение при сбое | `AccountStore` правильно: нечитаемое хранилище не трогается, отказ сейфа не ведёт к записи в открытом виде. | Тесты на desktop через `SoftwareVault`. |

## 4. Где уверенности нет

1. **Невидимый откат на программный ключ.** Android без TEE и iOS без Secure Enclave тихо
   создают программный ключ. Приложение не проверяет `KeyInfo.isInsideSecureHardware` и
   `kSecAttrTokenID` и не сообщает об этом. Заявления в PRIVACY и листинге должны говорить «в
   аппаратном модуле там, где он есть».
2. **StrongBox не запрашивается.** Ключ живёт в TEE, а не в отдельном чипе.
3. **iOS-код не выполнялся.** Вероятные места отказа: генерация в Secure Enclave, порядок
   `CFRelease`, декодирование результата расшифровки.
4. **Desktop и web без защиты.**
5. **Ключ не привязан к аутентификации** ни на одной платформе. Замок приложения (idea/06) —
   слой интерфейса, не криптография. Осознанное решение: 2FA нужен на каждом открытии.

## 5. Закрывает ли это план `.ai-notes/done/ssh-new`

В исходном виде (01–04) — нет. План решает те же вопросы для SSH-ключей и только на Android.
Сейф 2FA он не трогает, а привязку к аутентификации для него прямо отвергает. iOS в плане
нет вовсе; desktop и web — «в v1 нет сервиса».

## 6. Модель владельца и что она меняет

«Где есть чип — чип. Где нет — пароль ssh-ключа как корень доверия. Ключи в чипе, если можно;
если нельзя — честно писать, где лежат. Обе платформы.»

Записано в заметке 05 как три уровня хранения с обязательной надписью:

| Уровень | Где закрытая половина | Надпись | Подтверждение |
|---|---|---|---|
| 1. Резидентный | внутри чипа | «Хранится в защищённом чипе, не покидает его» | отпечаток / Face ID / код, проверяет чип |
| 2. Запечатан чипом | в файлах, под ключом-обёрткой из чипа | «Зашифрован ключом из защищённого чипа» | то же; ключ в памяти миллисекунды |
| 3. Запечатан паролем | в файлах, исходный `openssh-key-v1` | «Лежит в файлах, защищён только паролем ключа» | ввод пароля, проверяет bcrypt |

Уровень 3 есть на каждой платформе, поэтому кольцо регистрируется везде.

**iOS.** «iOS не подходит» — неверно. Не подходит импорт в чип: Secure Enclave принимает только
P-256, созданные внутри него. Face ID ничего не расшифровывает ни на одной платформе; он
разрешает чипу одну операцию ключом-обёрткой. На iOS это `SecAccessControl` с `UserPresence`
и `PrivateKeyUsage`, соответствие параметрам Android — таблица 05 §4.2. Импортированные ключи
на iPhone — всегда уровень 2, созданный P-256 — уровень 1, но он не умеет age.

**Desktop и web.** Сейф 2FA становится age-файлом на свой ssh-ключ: запечатать открытым ключом
без промпта, распечатать паролем один раз за сессию хоста.

## 7. Решения владельца в этой сессии

- **D167.** Ключ без пароля не принимается. Пароль короче 12 символов ведёт в диалог «Задать
  пароль», который перешифровывает файл (`ssh-keygen -p`). Считается только длина, и это
  сказано рядом с полем.
- **D168, D170.** Полный бэкап хоста — один age-файл на ключи GitHub-аккаунта. В нём данные
  приложений, **не ключи**: ни один закрытый ключ в бэкап не попадает, только список
  отпечатков как подсказка к повторному импорту.
- **D171.** Секреты — сервис хоста: `runtime.secrets` с интерфейсом `StorageService`, хост
  запечатывает сам. Приложение не знает ни про чип, ни про ключ. `SecretVault` уходит из
  контракта приложений.
- **D172.** Бэкап делает хост обходом префиксов `app.<id>.` и `secret.<id>.`, не читая
  значений. Приложение участвует декларацией `BackupPolicy` в манифесте, по умолчанию целиком.

## 8. Что закрывается, что частично, что нет

**Полностью:** копия файлов приложения; использование без владельца на разблокированном
телефоне (уровни 1–2 через чип, 3 через пароль); извлечение через интерфейс; заблокированный
украденный телефон; подделка входа по SSH через приложение (только SSHSIG с namespace);
невидимый откат на программный ключ (после `storage()` и надписей); desktop и web без защиты.

**Частично:** код внутри процесса (одна операция в момент подтверждения; на уровне 3 ключ в
памяти на сессию); перебор пароля на копии файла (уровень 3, отсюда минимум 12 символов);
история клавиатуры при вставке.

**Нет:** скрипт того же origin в браузере; забытый пароль на уровне 3; ошибки чипа
производителя; аппаратная аттестация на iOS; доступ к кристаллу.

## 9. Что сделать до релиза iOS, независимо от плана SSH

1. `SecretVault.storage()` и предупреждение в 2FA, когда ключ программный.
2. iOS-тест для `IosKeychainVault` по образцу Android-теста, в `verify.sh` на Mac.
3. Шаг CI с эмулятором для `connectedDebugAndroidTest` в `services/vault`.
4. Переписать `play/PRIVACY.md` и листинг: «в защищённом хранилище платформы, в аппаратном
   модуле там, где он есть; на desktop и в браузере — под паролем ssh-ключа» (после D164).

## 12. Диагностика и самопроверка (заметка 06)

По решению владельца добавлена заметка `.ai-notes/done/ssh-new/06-diagnostics-and-self-test.md`:

- **Самопроверка на устройстве.** Код, который выполняет реальную криптографию временными
  ключами (seal/open, аппаратность, подмена, отказ без подтверждения, Secure Enclave, bcrypt,
  age, расположение файлов, обнуление памяти) и пишет отчёт по шагам с сырыми ошибками
  платформы. Одна реализация служит продукту, шагу 0 и iOS-тестам.
- **Цикл без Mac.** `ios.yml` собирает для устройства в TestFlight (нужны секреты подписи,
  вопрос 88), владелец запускает самопроверку на iPhone и отправляет отчёт. iOS считается
  проверенным только по зелёному отчёту с устройства (D180).
- **Одна ниточка диагностики.** `StorageDiagnostics` в контракте 3: осмотр на каждом старте,
  пульс (запечатанная константа, которая ловит потерю ключа до открытия 2FA), самопроверка по
  кнопке. Коды и факты в библиотеке, тексты в Unitool: `DiagnosticsStrings.en` как источник,
  `ru` как перевод, полноту проверяет компилятор.
- **Честные пометки везде.** Экран Storage & security, баннер на Home при статусе Unsafe и
  выше, бейджи в списке ключей, карточке ключа, шапке 2FA, экране бэкапа. Ни одной надписи от
  руки: только коды каталога 06 §6.1, тот же каталог для листинга и PRIVACY.
- **D176.** Сейф на ssh-ключе кэширует расшифрованные секреты, а не ключ; подпись спрашивает
  пароль снова.

Оценка ≈ 20,5 дней.

## 13. Разделение по репозиториям (заметка 07)

Решение владельца: в Superizer только контракты, типы, коды диагностики и платформо-независимая
механика хоста (`runtime.secrets`, обход префиксов для бэкапа, агрегатор диагностики, слоты
Settings, фейки). Все реализации — в Unitool: `services/ssh` (крипто, форматы, бэкенды Keystore,
Secure Enclave, пароль, агент, самопроверка), `services/vault`, `services/file-picker`,
`services/backup`, экраны и таблицы строк в `composeApp`. Отменяет D139. Superizer 0.4.0 — один
шаг, после него библиотека не меняется; остальные шаги — Unitool через `includeBuild`. В `superizer:ui` — только слоты `HostSection`,
`HostScreen`, `HomeBanner`; экраны в Unitool. Оценка ≈ 20,5 дней.
