# 07 — провод как общий канал: файлы, бэкап, дальше что угодно

> **Версия:** 1.1 · **Дата:** 2026-10-06 · Решения D343–D351
>
> 1.1 — ответы владельца 161–165 (08): файлы лежат только внутри Unitool (D352); спрашиваем
> всегда, вопрос приходит уведомлением или пушем (D353, D354); экран — «Link» (D357).

## 1. Что сказал владелец

> «Надо предусмотреть, что в приложении и CLI вообще будет канал связи через провод, не только на
> ssh, но чтобы и файлы можно было отправить и они появились в папке приложения. Или, например,
> сделать бэкап через этот сокет.»

До этой заметки канал был сшит под ssh-agent: потоки — это клиенты `SSH_AUTH_SOCK`, сообщение
`AGENT`. Теперь канал — общая шина между Unitool и CLI. ssh-agent — одна из служб на ней, рядом
файлы и бэкап. Канал Noise, сопряжение и трубы (01, 02 §3–§4) не меняются.

## 2. Потоки и службы (D343)

Меняется слой 3 из 02 §1: вместо «ретранслятора ssh-agent» — потоки со службами. Схема та же,
что у каналов SSH (RFC 4254 §5) и yamux: у каждого потока есть имя службы и своё окно.

| Сообщение | Кто шлёт | Поля |
|---|---|---|
| `HELLO` / `WELCOME` | компьютер / телефон | как в 02 §5, плюс список служб и их версии на каждой стороне |
| `OPEN s service params` | **любая** сторона | открыть поток `s` к службе. Компьютер берёт чётные номера, телефон — нечётные, как в HTTP/2 |
| `DATA s bytes` | обе | до 32 КиБ в одном кадре |
| `WINDOW s n` | обе | «можно прислать ещё n байт». Начальное окно — 256 КиБ на поток |
| `CLOSE s status reason` | обе | `ok`, `refused`, `cancelled`, `unknown-service`, `no-space`, `error` |
| `REFUSED`, `KEYS`, `PING` / `PONG` | | как в 02 §5 |

- Сообщения ssh-agent идут в `DATA` потока службы `ssh-agent`. Сообщения `AGENT` больше нет.
- Короткие службы (`ssh-agent`, `keys`, `decrypt`) отправляются первыми. Большие (`files.*`,
  `backup.*`) делят остаток по кругу. Кадр не больше 32 КиБ, поэтому подпись для `ssh` ждёт за
  гигабайтным файлом не дольше одного кадра.
- Незнакомая служба → `CLOSE unknown-service`. Новая служба не ломает старого собеседника.
- Код — `kit.link`, по-прежнему без ввода-вывода (02 §5).

Службы v1:

| Служба | Кто открывает | Что делает |
|---|---|---|
| `ssh-agent` | компьютер | протокол ssh-agent (02 §2, §6) |
| `keys` | компьютер | все ключи телефона с подробностями (06 §3, §7) |
| `decrypt` | компьютер | снять запись получателя (06 §5.2) |
| `files.put` | любая сторона | передать файл (§4) |
| `files.list`, `files.get` | компьютер | список папки «С компьютера» и «Для компьютера» на телефоне, забрать файл |
| `backup.export` | компьютер (или телефон, позже) | бэкап хоста по проводу (§5) |
| `backup.restore` | компьютер | восстановление по проводу (§5) |

## 3. Компьютер: один демон, два сокета (D344)

Демон — уже не «агент», а владелец провода: `unitool link run`.

| Сокет | Кто говорит | Протокол |
|---|---|---|
| `$XDG_RUNTIME_DIR/unitool/agent.sock` | `ssh`, `git`, `ssh-add` | чистый ssh-agent (02 §2) — `SSH_AUTH_SOCK` / `IdentityAgent` |
| `$XDG_RUNTIME_DIR/unitool/link.sock` | команды `unitool` | те же сообщения `OPEN` / `DATA` / `WINDOW` / `CLOSE`, но без Noise: каталог 0700, сокет только для своего пользователя |

Демон соединяет локальные потоки с потоками на проводе. Потоки, которые открывает телефон
(файл в сторону компьютера), демон обслуживает сам (§4.2).

Команды CLI (меняет D317 и D340; имена — ответ 165, D357):

| Команда | Что |
|---|---|
| `unitool link pair`, `devices`, `forget`, `run` | провод и сопряжение — бывшие `unitool agent …` |
| `unitool keys …` | все ключи (06 §3) — бывшие `agent keys` и `agent public-key` |
| `unitool files send FILE… [--phone NAME]` | файлы на телефон |
| `unitool files ls`, `files get NAME… [-o DIR]` | что лежит на телефоне в папках обмена, забрать |
| `unitool backup pull [-u LOGIN] [-o FILE]` | бэкап телефона на компьютер |
| `unitool backup push FILE [-i KEY]` | восстановить телефон из бэкапа |

Демон не запущен → команда запускает его сама (06 §6).

## 4. Файлы (D346, D347)

### 4.1. Компьютер → телефон

```console
$ unitool files send report.pdf photos/*.jpg
iPhone: waiting for you to accept on the phone…
report.pdf   2.1 MB  ✓
IMG_001.jpg  4.8 MB  ✓
2 files, 6.9 MB in 1.2 s; on the phone in Unitool, "From computer"
```

- На телефоне: «laptop отправляет 2 файла · 6,9 МБ: report.pdf, IMG_001.jpg — [Отклонить]
  [Принять]». Биометрия не нужна: это приём, а не секрет.
- **(1.1)** Спрашиваем всегда, переключателя «Принимать без вопроса» нет (ответ 162, D353).
  Unitool не на экране → уведомление: на Android — от foreground service, без канала и на
  iPhone — пуш через наш сервер (08 §3, D354). В пуше только «laptop · файлы для вас», имена
  файлов — на листе.
- `OPEN` несёт имя, размер и время изменения. Телефон заранее проверяет свободное место (иначе
  `no-space`), пишет в `.part` и переименовывает после `CLOSE ok` с SHA-256 всего файла.
- Имя очищается: без `/`, `\`, `..`, управляющих символов, не длиннее 255 байт. Совпало с
  существующим → `report (2).pdf`. Файл не перезаписывается никогда.
- Докачки в v1 нет: оборвалось — `.part` удаляется, файл отправляется заново.

**Папка приложения** (1.1, ответ 161 — «только unitool», D352, подробно 08 §2):

| | Где | Кто видит |
|---|---|---|
| Android, все версии | `filesDir/link/from-computer/`, внутренняя память | только экран файлов Unitool |
| iOS | `Library/Application Support/link/from-computer/`, без `UIFileSharingEnabled` | только экран файлов Unitool; в «Файлах» папки нет (вопрос 169) |

В Unitool — экран «Файлы с компьютера»: список, «Открыть в…», «Поделиться», «Сохранить в…»,
«Удалить», «Отправить на компьютер». Наружу файл выходит только так, по действию человека.
Мини-приложения папку не видят: дверь для них — позже (§6).

### 4.2. Телефон → компьютер

- В экране файлов — «Отправить на компьютер». На Android ещё и пункт «Unitool → на компьютер» в
  системном «Поделиться» (`ACTION_SEND` / `ACTION_SEND_MULTIPLE`). На iOS для этого нужно
  расширение «Поделиться» — отдельная цель в Xcode, это позже.
- Телефон открывает `files.put` к компьютеру. Демон пишет файл в `~/Downloads/Unitool/`
  (`$XDG_DOWNLOAD_DIR`, ответ 163) по тем же правилам: `.part`, SHA-256, без перезаписи. Потом
  показывает уведомление «iPhone прислал report.pdf».
- Компьютер ничего не спрашивает: телефон сопряжён, а отправку нажал человек.
- `unitool files get` забирает то, что человек положил в папку «Для компьютера» на телефоне
  (`filesDir/link/to-computer/` или `Application Support/link/to-computer/`, D352). Так можно взять
  файл, не трогая телефон.

## 5. Бэкап по проводу (D348, D349)

Бэкап хоста уже есть (ssh-new/05 §3, `HostBackup`):
- `export(recipients, reason)` спрашивает человека, открывает секреты сейфом и шифрует age
  ключам получателей. Сегодня файл уходит в «Поделиться»;
- `read(file)` читает и зашифрованный файл, и бандл, уже открытый на компьютере
  (`age -d -i ~/.ssh/id_ed25519`);
- `restore(...)` спрашивает и заменяет данные приложений.

Провод — ещё одна дорога для того же файла. Новой криптографии нет.

### 5.1. `unitool backup pull`

```console
$ unitool backup pull -u octocat
iPhone: confirm the backup on the phone…
unitool-backup-2026-10-06.age  84 KB  for 2 keys of octocat: SHA256:Ab3dE…, SHA256:Xy9Lm…
Open it with: age -d -i ~/.ssh/id_ed25519 unitool-backup-2026-10-06.age
```

- **Получателей выбирает телефон**, а не компьютер. Компьютер может передать только логин GitHub
  (`-u`). Ключи телефон скачивает сам и показывает на листе вместе с отпечатками. Без `-u`
  берётся логин прошлого бэкапа, который телефон запоминает.
- Открытых ключей от компьютера бэкап не принимает. Иначе взломанный сопряжённый компьютер
  подложил бы свой ключ и получил бы все данные приложений, а человек увидел бы только
  незнакомый отпечаток (ответ 164: да).
- Дальше — обычный `export` со своим листом и биометрией. На компьютер приходит age-файл.
  Компьютер сможет его открыть, только если на нём лежит один из закрытых ключей этого аккаунта
  GitHub.
- Бэкап по-прежнему несёт данные приложений, а не SSH-ключи (ssh-new D170).

### 5.2. `unitool backup push`

- `unitool backup push FILE` отправляет зашифрованный файл. Телефон открывает его своей связкой
  ключей — если нужный ключ на телефоне есть.
- `unitool backup push FILE -i ~/.ssh/id_ed25519` открывает age **на компьютере** (`kit.age`,
  только в памяти, на диск ничего не пишется) и шлёт бандл по Noise. Это путь для нового
  телефона, на котором ключей ещё нет. `HostBackup.read` такой бандл уже понимает.
- На телефоне открывается обычный экран восстановления: план, выбор приложений, «и настройки». Всё
  подтверждает человек. Компьютер не выбирает, что восстанавливать.

### 5.3. Позже

- Бэкап при подключении, не чаще раза в день: телефон сам открывает `backup.export` к демону,
  файл ложится в `~/Unitool/Backups/<телефон>/`. Но `export` каждый раз спрашивает биометрию, и
  «сам» означает «уведомление: сделать бэкап?». Отдельное решение.
- Бэкап файлов компьютера на телефон — это `unitool files send` папкой. Отдельной функции нет
  (ответ 164: «тот же бэкап, который уже есть, с шифрованием»).

## 6. Телефон: реестр служб (D345)

- `services/phone-link` держит реестр `LinkService`: имя, версия, `open(params, stream)`. Службы
  v1 — из таблицы §2, все хостовые.
- Службы мини-приложений Superizer (например, «прогресс» получает файлы по проводу) — позже и
  отдельным контрактом: сегодня у приложения нет двери к проводу, и её проектирование — отдельный
  разговор.
- Экран «Подпись для компьютера» становится экраном **«Link»** (1.1, рабочее имя, ответ 165,
  D357; в 1.0 — «Компьютер по проводу»): список компьютеров, у каждого — SSH, «Файлы», «Бэкап»,
  переключатели. Файлы и бэкап нужны не только тем, у кого SSH-ключи, поэтому вход — из
  «Настроек», а не только за кодом `{ssh-keys}` (меняет предложение вопроса 149).
- iOS: передача идёт, пока Unitool открыт, как и подпись. Экран не гаснет, пока идёт передача.
  Ушёл в фон посреди файла → поток закрывается, `.part` удаляется, компьютер говорит «прервано:
  Unitool ушёл в фон».
- Android: foreground service `connectedDevice` держит и длинные передачи.

## 7. Скорость (D350)

- USB 2.0 даёт практически 30–40 МБ/с. Через usbmux и AOA — меньше, точная цифра — разведка S7.
- Шифр канала — наш ChaCha20-Poly1305 на Kotlin. Его скорость в нативном бинаре и на телефонах
  неизвестна. Цель — не меньше 10 МБ/с.
- Если упираемся в шифр, на телефонах есть платформенные: на Android `ChaCha20-Poly1305` в JCA
  (API 28+), на iOS CryptoKit `ChaChaPoly`. Noise описывает и `AESGCM`, но смена шифра —
  несовместимая версия канала, поэтому решаем до первого выпуска.

## 9. Тесты

- `kit.link`: два потока сразу — короткий проходит, пока идёт большой; окно — отправитель
  останавливается и продолжает после `WINDOW`; незнакомая служба; `CLOSE` посреди файла.
- Сквозной JVM-тест (04 §4.2) дополняется:
  - файл 50 МБ туда и обратно, SHA-256 сходится;
  - `ssh` входит, пока идёт файл;
  - имена `../../x`, `a/b`, совпадения, нет места;
  - обрыв посередине — `.part` удалён.
- Бэкап: `backup pull` даёт файл, который открывает настоящий `age -d -i`; `backup push -i`
  восстанавливает на desktop-хосте; лист показывает ключи, которые телефон скачал сам, а
  переданные компьютером ключи не принимаются.
- Канарейка (ssh-new/03): закрытых ключей нет ни в трубе, ни в бэкапе.

## 10. Решения этой заметки

|---|---|
| D343 | Провод — общий канал приложения и CLI: потоки со службами (`OPEN service`, `DATA`, `WINDOW`, `CLOSE status`), открывать может любая сторона, окна на поток, кадры до 32 КиБ, короткие службы первыми. ssh-agent — одна из служб. Меняет слой 3 из 02 (D309, D312) (§2) |
| D344 | Демон `unitool link run` — единственный владелец провода; два сокета: `agent.sock` (чистый ssh-agent) и `link.sock` (потоки для команд unitool). Команды `link`, `keys`, `files`, `backup`; приложение `agent` растворяется (меняет D317, D340) (§3) |
| D345 | (1.1: экран «Link», D357) На телефоне — реестр `LinkService` в `services/phone-link`, в v1 только службы хоста; экран «Компьютер по проводу» с SSH, файлами и бэкапом, вход из «Настроек» (§6) |
| D346 | (1.1: спрашиваем всегда — D353; папка только внутри Unitool — D352) Файлы с компьютера: подтверждение на телефоне (или «без вопроса» по настройке), `.part` + SHA-256, без перезаписи, проверка места. Папка: iOS — `Documents/From computer` в «Файлах»; Android 10+ — `Download/Unitool` через MediaStore; Android 7–9 — внутри приложения; экран файлов в Unitool (§4.1) |
| D347 | Файлы с телефона: из экрана файлов и из «Поделиться» на Android; на компьютере — `~/Downloads/Unitool/` с уведомлением; `files get` забирает из папки «Для компьютера» (§4.2) |
| D348 | `backup pull`: тот же `HostBackup.export` с листом и биометрией; получатели — ключи GitHub, которые телефон скачал сам по логину; ключей от компьютера бэкап не берёт (§5.1) |
| D349 | `backup push`: зашифрованный файл (открывает телефон) или с `-i` открытый на компьютере в памяти; восстанавливать что — выбирает человек на телефоне (§5.2) |

| D351 | Обобщённый канал — сразу в v1 (+2 дня); файлы и бэкап — после SSH v1, ≈ 7 дней (§8) |
