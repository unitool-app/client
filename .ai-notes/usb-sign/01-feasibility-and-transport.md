## 1. Вердикт

| Часть | Реально? | Что мешает |
|---|---|---|
| Ключ и подпись на телефоне | **уже сделано**: связка ключей, чип, промпт, протокол ssh-agent (04 §1) | ничего |
| Формат подписи для OpenSSH | **уже сделано**: `EcdsaDer`, RSA-SHA2, Ed25519, сверка с `ssh-keygen` | ничего |
| iPhone ↔ компьютер по USB | **да**, без jailbreak и без закрытых API: usbmuxd + слушатель на loopback (§2) | работает, **только пока Unitool открыт на экране** |
| Android ↔ компьютер по USB | **да**, без режима разработчика: Android Open Accessory (§3) | телефон в режиме аксессуара не отдаёт файлы (MTP) до переподключения кабеля; нужны права на USB на Linux |
| Агент на компьютере | **да**: приложение нашего нативного CLI (03 §1) | работает там, где собран CLI unitool, сейчас это Linux (D326) |
| Сервер SSH без изменений | **да**: обычный ключ `ecdsa-sha2-nistp256` / `ssh-ed25519` / `rsa-sha2-*` в `authorized_keys` | ничего |
| Показать, куда вход | **частично**: пользователь подписан, ключ сервера проверяется, имя сервера — нет (02 §7) | имени хоста в протоколе нет вовсе |

Итог: делается. Ключи, подпись в чипе и протокол агента на телефоне уже написаны и проверены.
Новое — труба по USB, канал с сопряжением, агент в CLI и лист запроса. Единственное настоящее ограничение — фон на iOS
(§2.4). Обойти его по кабелю нельзя.

## 2. iPhone: usbmuxd

### 2.1. Как это работает

```
desktop                                    iPhone
процесс ── /var/run/usbmuxd ── USB ──► 127.0.0.1:P  ← Unitool слушает обычным сокетом
          «Connect DeviceID, PortNumber»
          ответ Result 0 → сокет стал трубой байтов
```

- На телефоне — обычный BSD-сокет, `bind` на loopback, `listen`. Закрытых API нет.
- На компьютере — демон usbmuxd. На macOS он системный, на Linux это `usbmuxd` из
  libimobiledevice, протокол у них один.
- Тот же путь годами используют PeerTalk (в App Store: Duet Display, Facebook Origami —
  https://github.com/rsms/peertalk) и WebDriverAgent через `iproxy`. В сентябре 2026 `iproxy` к
  WebDriverAgent работает на iOS 26.7 и бете iOS 27 (appium-xcuitest-driver #2985). Перенос
  служб разработчика в CoreDevice/RemoteXPC в iOS 17 этот путь не сломал: тот касается
  отладчика и запуска приложений, а не `Connect` к порту приложения.
- Сетевого разрешения «Локальная сеть» не нужно: «слушать и принимать входящие TCP» в TN3179
  помечено «нет».

### 2.2. Протокол usbmuxd

Apple его не публикует. Фактическая спецификация — исходники libusbmuxd
(`include/usbmuxd-proto.h`, `src/libusbmuxd.c`):
- заголовок `u32 length, u32 version, u32 message, u32 tag`; `message = 8` — тело в XML plist;
- в каждом plist есть `MessageType`, `ClientVersionString`, `ProgName`, `kLibUSBMuxVersion`;
- запросы: `ListDevices` (ответ `DeviceList`), `Listen` (события `Attached`, `Detached`,
  `Paired`), `Connect` (`DeviceID`, `PortNumber = htons(port)` — порт в сетевом порядке внутри
  целого числа plist);
- ответ `Result`: `Number` 0 — успех, 2 — нет устройства, 3 — отказ в соединении. После 0 этот же
  сокет — сырая труба.

Свой клиент — около 200 строк (03 §1.6). libimobiledevice в бинарь не нужен.

### 2.3. Условия

- Телефон доверяет компьютеру («Доверять этому компьютеру?» — один раз). Отказывает ли телефон в
  `Connect` без доверия — не проверено (разведка S1).
- Телефон разблокирован. USB Restricted Mode: если телефон заблокирован больше часа, новые
  соединения по USB не открываются до разблокировки (https://support.apple.com/111806). На
  практике это не мешает: приложение всё равно должно быть на экране (§2.4).
- На Linux — пакет `usbmuxd`. Стоит ли он в чистой Ubuntu Desktop — разведка S3.
- **Сокет usbmuxd на Linux — `0666`** (`src/main.c`): к нему, а значит к порту приложения, может
  подключиться любой локальный пользователь. Отсюда свой канал с сопряжением (02 §3).

### 2.4. Фон — главное ограничение

- iOS приостанавливает приложение вскоре после ухода в фон. На вопрос «как сделать сетевой
  сервер, работающий в фоне» ответ Apple DTS — «никак»
  (https://developer.apple.com/forums/thread/685525). Фоновая задача даёт около 30 секунд.
- Слушающий сокет Apple советует закрывать при уходе в фон и открывать заново при возврате.
- `external-accessory` — только для MFi-аксессуаров, компьютер им не является.
- Единственный честный фоновый путь — Bluetooth LE (`bluetooth-peripheral`). Так делали Krypton и
  Keythra (§4).
- Злоупотреблять фоновыми режимами ради удержания сокета запрещает правило ревью 2.5.4.

Значит, в v1 на iPhone подпись по кабелю — это «Unitool открыт на экране». Компьютер, не найдя
приложения, зовёт человека уведомлением на своём экране и ждёт (03 §1.5). Разбудить приложение
уведомлением **на телефоне** можно только пушем с сервера: локальное уведомление
приостановленное приложение не покажет.

**Ответ владельца (148):** v1 так, а следующий шаг записан сразу — пуш-будильник. Компьютер через
сервер шлёт пуш, человек нажимает уведомление, Unitool открывается, и компьютер подключается к
телефону по тому же кабелю (05).

### 2.5. Ревью App Store

Правила, запрещающего слушать loopback, нет: это публичные API (2.5.1). PeerTalk-приложения
прошли ревью. Для TestFlight внутренним тестерам ревью не нужно вовсе. В заметке для ревью стоит
одной строкой объяснить, зачем слушатель.

## 3. Android

### 3.1. Android Open Accessory — основной путь

```
desktop (USB host)                          телефон
control 51 → версия протокола AOA
control 52 × 6 → строки: m42.cx / Unitool Link / описание / 1 / URL / серийный
control 53 → старт
                    телефон переподключается как 18d1:2d00 (или 2d01 вместе с adb)
bulk OUT/IN ◄────────────────────────────►  UsbManager.openAccessory() → ParcelFileDescriptor
```

- Спецификация живая: https://source.android.com/docs/core/interaction/accessories/aoa.
  `openAccessory()` не устарел. Проводной Android Auto (aasdk) работает именно так.
- Режима разработчика не нужно. Приложению — фильтр `accessory_filter.xml` и
  `USB_ACCESSORY_ATTACHED`; система сама спросит «Открыть Unitool для Unitool Link?».
- Ограничения:
  - AOA и MTP одновременно не работают. Пока телефон аксессуар, файлы с компьютера не видны —
    до переподключения кабеля;
  - на Android 10 и ниже нельзя опускать строку версии: при фильтре по версии телефон
    перезагрузится. Мы её всегда шлём;
  - Android 16 с Advanced Protection не открывает новых соединений по USB, пока телефон
    заблокирован (https://www.androidauthority.com/android-16-usb-data-advanced-protection-3548018);
  - поведение Samsung и других — не проверено (разведка S2).
- Права на компьютере:
  - Linux: нужен доступ к `/dev/bus/usb/…` — и к исходному устройству телефона (для команд
    51–53), и к `18d1:2d00`. Правила android-udev-rules покрывают `18d1:2d00`–`2d05`; что дают
    правила libmtp и `uaccess` для исходного устройства — разведка S3;
  - macOS: libusb работает без kext и без root, если устройство не занято драйвером ядра. У нас
    будет IOKit, условия те же.
- На Linux libusb не нужен: те же запросы делает `ioctl` usbfs (`USBDEVFS_CONTROL`,
  `USBDEVFS_BULK` или асинхронные URB). Бинарь остаётся без новых зависимостей.

### 3.2. adb — не делаем

**Ответ владельца (147): «сразу аксессуар».** adb нет ни основным путём, ни переключателем.

Что рассматривалось: `adb forward` или сразу протокол adb-сервера до `localabstract:` (так делает
scrcpy). Плюс — работает сразу, без разведки AOA. Минусы:
- нужны режим разработчика и отладка по USB;
- компьютер с доступом к adb получает оболочку: ставит приложения, снимает экран, **нажимает
  кнопки**. Кнопку «Подписать» он нажать может. Биометрию — нет, а ключ в чипе всегда под
  отпечатком или своим паролем (ssh-new D247). Но держать отладку включённой — плохая привычка
  для телефона, который хранит ключи.

Если AOA на телефоне владельца не заведётся (разведка S2), adb не становится запасным путём
сам собой: это возврат к владельцу.

### 3.3. Фон на Android — не проблема

- Foreground service типа `connectedDevice` держит аксессуар, пока кабель вставлен. Нужны
  `FOREGROUND_SERVICE_CONNECTED_DEVICE` в манифесте, выполненное предусловие (разрешение на
  USB-устройство или аксессуар) и декларация в Play Console для targetSdk 34+
  (https://developer.android.com/develop/background-work/services/fgs/service-types).
- Активити из фона с Android 10 не запускаются. Разрешённый путь — уведомление, которое человек
  нажимает. На Android 14–15 у `PendingIntent` надо явно разрешить запуск.
- `USE_FULL_SCREEN_INTENT` на Android 14+ дают только звонилкам и будильникам, Play его
  отзывает — не используем.

### 3.4. USB-модем — нет

Режим модема создаёт сеть между телефоном и компьютером, но его включают вручную каждый раз, и
интернет компьютера идёт через телефон. Не годится.

## 4. Похожие проекты

| Проект | Как устроен | Что берём |
|---|---|---|
| **akr** (Akamai, Rust, живой) | HTTP-очередь через `mfa.akamai.com` + пуш APNs/FCM; libsodium `crypto_box`; сопряжение по QR; ключи `sk-ecdsa-sha2-nistp256@openssh.com`; расширения агента игнорирует, `session-bind` нет. USB и Bluetooth нет | сопряжение по QR, язык листа подтверждения |
| **Krypton / kr** (архив, предок akr) | AWS SQS + SNS-пуш, Bluetooth LE; QR с открытым ключом компьютера; `krssh` как ProxyCommand разбирал обмен ключами и отдавал агенту ключ хоста — привязка к серверу до появления `session-bind` | идея «телефон знает ключ хоста» |
| **Secretive** (macOS, v4.0.0, 2026-09) | агент на Secure Enclave Mac, Touch ID, без экспорта. `session-bind` разбирает и проверяет подпись хоста, но пока отклоняет: «disabled until forward enforcement is handled» | сверка нашего разбора `session-bind` |
| **Keythra** | iPhone + мост на Mac по Wi-Fi или BLE | ближайший по смыслу, но без кабеля |
| **pocket-key** | Android Keystore по BLE | — |
| **PhoneFIDO-Key** | Android как USB-ключ FIDO, только с root (режим gadget) | подтверждает: без root телефон не притворится USB-ключом |

Проекта «iPhone по usbmux как SSH-ключ» нет ни на GitHub, ни в сети. Путь новый, но каждая его
часть отдельно проверена: труба (PeerTalk, WebDriverAgent), агент (Secretive, наш `AgentInteropTest`),
подтверждение на телефоне (akr, Krypton).

## 5. Другие пути — позже или никогда

| Путь | Плюс | Минус | Когда |
|---|---|---|---|
| TCP по локальной сети | без кабеля, тот же канал Noise — новая только труба | iOS: тот же фон; Bonjour-объявление спросит «Локальная сеть»; сеть бывает гостевой | после v1, дёшево |
| Bluetooth LE | **единственный способ подписать на iPhone без открытия приложения** (`bluetooth-peripheral`) | BLE на desktop: BlueZ через D-Bus на Linux, CoreBluetooth на macOS — много кода; медленно | отдельной заметкой, если фон на iOS станет главной жалобой |
| Пуш-будильник + кабель | iPhone подписывает и из фона: пуш открывает Unitool, данные идут по кабелю | нужен сервер remote-progress (idea/08) | **следующий шаг после v1, заметка 05** (ответ 148) |
| Сервер-ретранслятор данных (как akr) | работает без кабеля откуда угодно | сервер видит трафик (пусть и шифрованный), задержка, зависимость от сети | нет: данные идут по кабелю, сервер только будит |
| Свой `SecurityKeyProvider` для OpenSSH (`sk-api.h`) | без своего агента: `ssh` сам грузит библиотеку | ключи только `sk-*`: сервер должен их принимать, обычный ключ брифа не подходит | нет |
| Телефон как FIDO-ключ через hybrid (caBLE) | стандарт | в libfido2 1.17 гибридного транспорта нет; ключи passkey привязаны к сайту, не к `ssh:` | нет |
| Телефон как USB-устройство HID/FIDO | выглядел бы как YubiKey | на Android только с root, на iOS невозможно | нет |
