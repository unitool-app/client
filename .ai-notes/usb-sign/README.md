## Короткий ответ

**Реально, и большая часть телефонной стороны уже написана.**

1. **Что уже есть** (04 §1):
   - ключи в чипе: P-256 в Secure Enclave, Keystore/StrongBox на Android;
   - подпись после Face ID или отпечатка;
   - протокол ssh-agent, проверенный настоящими `ssh-add` и `ssh-keygen`;
   - подпись ECDSA в формате SSH (`mpint r`, `mpint s`).

   Пункты брифа §3–§6 и его этапы 1–2 закрыты.
2. **USB к iPhone** (01 §2).
   - Без jailbreak и без закрытых API: Unitool слушает обычный сокет на `127.0.0.1`, компьютер
     доходит до него через usbmuxd.
   - Так работают PeerTalk (Duet Display в App Store) и WebDriverAgent, в том числе на iOS 26 и
     бете iOS 27.
   - В фоне iOS приложение не слушает. В v1 подпись идёт, только когда Unitool открыт на экране:
     компьютер, не найдя телефона, зовёт человека уведомлением на своём экране и ждёт.
   - **Следующий шаг записан сразу (05):** компьютер через сервер шлёт пуш, человек нажимает
     уведомление, Unitool открывается, и компьютер подключается к нему по кабелю. Пуш только
     будит телефон и ничего не открывает сам.
3. **USB к Android** (01 §3).
   - Только Android Open Accessory: без режима разработчика, как проводной Android Auto.
   - Foreground service держит канал в фоне. Запрос приходит уведомлением, нажатие открывает лист,
     дальше отпечаток.
   - Цена: пока телефон в режиме аксессуара, файлы с компьютера не видны.
   - adb не делаем.
4. **Канал** (02).
   - Ни одна труба не проверяет собеседника: сокет usbmuxd на Linux открыт всем (`0666`).
   - Поэтому поверх трубы — стандартный Noise (`KK`, для сопряжения `XXpsk3`) на примитивах,
     которые уже есть.
   - Сопряжение — QR в терминале, телефон сканирует его камерой. Своих схем нет.
5. **Компьютер — ретранслятор** (02 §2). Протокол ssh-agent пересылается телефону как есть: у
   телефона уже есть агент. Сам агент — приложение `agent` CLI unitool (03 §1): `unitool agent
   pair / devices / keys / public-key / run`. Работает там, где собран CLI, сейчас это Linux.
6. **Что телефон показывает честно** (02 §7).
   - Имя пользователя входит в подписанные данные.
   - Ключ хоста сервера телефон проверяет сам — по `session-bind@openssh.com` или по входу
     hostbound в OpenSSH 8.9+.
   - Имя сервера даёт человек на телефоне.
   - Что говорит компьютер, помечено «не проверено». Имени хоста в протоколе SSH нет вовсе.
   - **Если ключ сервера не проверен, телефон отказывает** — без листа, с причиной (ответ 151).
     Нужен OpenSSH 8.9+ на компьютере (Ubuntu 22.04+).
7. **Ключи телефона — во всём CLI** (06).
   - Телефон на проводе — такой же источник ключей, как GitHub, файл и `SSH_AUTH_SOCK`. Ссылки
     `phone:…`, `gh:LOGIN`, `file:PATH`, `agent` работают в любой команде, где берётся ключ.
   - `unitool keys` показывает все открытые ключи одним списком. Компьютер видит все ключи
     телефона, а не только выбранные.
   - `crypt encrypt` шифрует и ключам телефона: открытого ключа из кэша хватает и без кабеля.
   - Подпись телефоном — SSHSIG через агента; git подписывает коммиты ключом телефона уже так.
   - Расшифровка по проводу: телефон снимает запись получателя сам и отдаёт только ключ файла.
     Сырых операций закрытым ключом наружу нет.
8. **Провод — общий канал** (07).
   - Поверх Noise идут потоки со службами; ssh-agent — одна из них, рядом `files.*` и
     `backup.*`.
   - Открывать поток может любая сторона. Короткие запросы не ждут за большими файлами.
   - На компьютере — демон `unitool link run` с двумя сокетами: `agent.sock` для `ssh` и
     `link.sock` для команд `unitool`.
   - `unitool files send` кладёт файлы в папку внутри Unitool. Другие приложения и «Файлы» её не
     видят; наружу файл выходит только по действию человека: «Открыть в…», «Поделиться»,
     «Сохранить в…» (1.4, ответ 161). Обратно — «Отправить на компьютер», файл попадает в
     `~/Downloads/Unitool`.
   - `unitool backup pull / push` — существующий бэкап хоста по проводу. Получателей бэкапа
     выбирает телефон, а не компьютер.
9. **Вопросы — пушем, свой сервер** (08).
   - Человека спрашиваем всегда, в том числе о каждой пачке файлов. Unitool не на экране —
     уведомление; без канала — пуш через наш сервер. В пуше только «laptop · файлы для вас»,
     подробности — на листе из канала.
   - Сервер — свой. Предложение: один сервер Unitool, remote-progress — его первая служба
     (вопрос 166).
   - Следующим шагом сервер может стать ещё одной трубой под тем же Noise: связь без кабеля,
     переключатель у компьютера, по умолчанию выключен (вопрос 167).
   - Рабочее имя — link: экран «Link» в «Настройках».
10. **Готового такого решения нет** (01 §4). akr и Krypton ходят через сервер и пуш, Secretive —
   только Mac, Keythra — Wi-Fi и Bluetooth. Путь по usbmux новый, но каждая часть проверена
   отдельно.
11. **Оценка** (04 §2): ≈ 26,5 дня на v1 — SSH, основа ключей телефона в CLI и общий канал с
    потоками. Дальше пуш-будильник +4,5 (после сервера), `crypt` по проводу +3
    (после `crypt`), файлы и бэкап +7, связь через сервер ≈ +6 (если 167 — да). Первые 2
   дня — разведка на настоящих телефонах. Если не пройдёт S1 (iPhone) или S2 (Android) —
   остановка и возврат к владельцу.
