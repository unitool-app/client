# 06 — ключи телефона во всём CLI: все открытые ключи видны, подпись и расшифровка по проводу

> **Версия:** 1.1 · **Дата:** 2026-10-06 · Решения D335–D342
>
> 1.1 — провод стал общим каналом (07): `keys` и `decrypt` — службы канала, а не расширения
> агента; демон — `unitool link run`, команды — через `link.sock` (D340 переписано).

## 1. Что сказал владелец

> «Добавь в план, чтобы CLI во всех режимах мог брать публичные ключи или подпись из телефона.
> Надо сделать, чтобы все публичные было видно. Например, если шифруем, можно выбрать не только
> ключи с GitHub, но и по проводу.»

Это значит:
- провод — источник ключей для **всего** CLI, а не только для `ssh`;
- в любой команде, которая берёт ключ, ключи телефона стоят рядом с GitHub и файлами;
- телефон показывает компьютеру **все** свои открытые ключи, а не только выбранные (меняет D311 и
  D313, §7);
- закрытые операции (подпись, позже расшифровка) делает телефон после листа и биометрии.

## 2. Источники ключей (D335)

| Источник | Ссылка на ключ | Что даёт | Без кабеля и сети |
|---|---|---|---|
| Телефон по проводу | `phone`, `phone:<комментарий или начало отпечатка>`; при нескольких телефонах — `phone@<имя>:…` | открытые ключи всех ключей телефона; подпись; расшифровка (§5.2) | открытые ключи — из кэша с пометкой «cached»; подпись и расшифровка — только с кабелем |
| GitHub | `gh:LOGIN` — то же, что `-u LOGIN` у `crypt` | открытые ключи | нужен интернет (crypt, вопрос 143) |
| Файл | `file:PATH` — то же, что `-R FILE` / `-i KEY` | открытые ключи; закрытый, если это файл ключа | да |
| ssh-agent | `agent` — любой агент в `SSH_AUTH_SOCK`, хоть OpenSSH, хоть наш | открытые ключи и подпись | да |
| Строка | `-r "ssh-ed25519 AAAA…"` | один открытый ключ | да |
| Отпечаток | `SHA256:Ab3dE` (начало) | ищет во всех источниках сразу | — |

Правило одно для всех команд: где команда берёт ключ или список ключей (`-r`, `-R`, `-i`, `-k`),
там работает ссылка с приставкой. Голые формы значат то же, что и раньше. Пример:

```console
$ unitool crypt encrypt report.pdf -r phone:home -r gh:octocat
```

Разбор ссылок — чистая функция в kit (`kit.keys.KeyRef`), один код для CLI и, позже, телефона.

## 3. Все открытые ключи в одном списке (D336)

Новое приложение CLI `keys`:

```console
$ unitool keys
SOURCE              TYPE       FINGERPRINT       COMMENT                 USE
phone iPhone/cable  ECDSA 256  SHA256:Qq1Rt…     work · chip             ssh · sign
phone iPhone/cable  ED25519    SHA256:Ab3dE…     home · sealed by chip   ssh · sign · encrypt · decrypt
file                ED25519    SHA256:Lm8Pq…     ~/.ssh/id_ed25519.pub   ssh · sign · encrypt · decrypt
agent               RSA 4096   SHA256:Xy9Lm…     deploy@ci               ssh · sign · encrypt
$ unitool keys gh:octocat
$ unitool keys show phone:home          # строка authorized_keys, уровень хранения, что умеет
```

- Без аргументов список собирается из телефона (с кабелем — живьём, без него — из кэша), файлов
  `~/.ssh/*.pub` и `SSH_AUTH_SOCK`. Список GitHub — только по `gh:LOGIN`: сеть без спроса CLI не
  трогает.
- Колонка `USE` честно говорит, что можно сделать с ключом здесь и сейчас: `ssh` — вход через
  агента; `sign` — подпись SSHSIG; `encrypt` — получатель `ucrypt` 1.0 (ECDSA — нет, crypt D301,
  вопрос 159); `decrypt` — закрытая часть досягаема.
- Бывшие `unitool agent keys` и `unitool agent public-key` (03 §1.1) — это `unitool keys phone` и
  `unitool keys show phone…` (07 §3).

## 4. Выбор ключей в меню каждой команды (D337)

Шаг «выбор ключей» — общий для всех приложений CLI, в модуле `unitool-cli/keys`. Первым идёт
телефон, потому что он свой:

```
Crypt · encrypt
Whose keys?
  1) My phone       iPhone, cable connected, 3 keys
  2) A GitHub user  enter a login
  3) A file         authorized_keys or .pub
  4) ssh-agent      $SSH_AUTH_SOCK, 1 key
> 1
Keys of iPhone (over the cable):
  1) ED25519  256   128-bit   SHA256:Ab3dE…  home
  2) RSA      4096  ~140-bit  SHA256:Xy9Lm…  old-laptop
  -  ECDSA    256             SHA256:Qq1Rt…  work: ECDSA keys cannot receive files yet
Keys to encrypt to, numbers like 1,2 [Enter: all]: 1
More keys from another source? [y/N]: n
report.pdf → report.pdf.ucrypt, 100 KB, for 1 key of iPhone; read back and checked
The same as one command: unitool crypt encrypt report.pdf -r phone:SHA256:Ab3dE
```

Телефона нет на кабеле и в кэше пусто → строки 1 нет. Кэш есть, а кабеля нет → «iPhone, not
connected, 3 keys (cached)»: для шифрования открытого ключа из кэша достаточно.

## 5. Закрытые операции телефона в CLI

### 5.1. Подпись (D338)

- `KeyOps.sign(ref, namespace, data)` в `unitool-cli/keys`. Для телефона это SSHSIG: CLI собирает
  подписываемую структуру (`"SSHSIG" ‖ namespace ‖ reserved ‖ hash_alg ‖ H(data)`) и шлёт обычный
  `SIGN_REQUEST`. Телефон узнаёт SSHSIG (02 §7.1), показывает лист «Подпись: file · SHA512:… ·
  просит: `unitool sign`» и подписывает после биометрии (вопрос 157).
- Подпись проверяется настоящим `ssh-keygen -Y verify`.
- **git уже сейчас** подпишет коммит ключом телефона без нового кода CLI: `gpg.format=ssh`,
  `user.signingKey = "key::ecdsa-sha2-nistp256 AAAA…"` — git зовёт `ssh-keygen -Y sign`, а тот
  идёт в агента из `SSH_AUTH_SOCK`.
- Своё приложение подписи в CLI (`unitool sign` / `unitool verify`, файлы `.sig`, совместимые с
  `ssh-keygen -Y`) — вопрос 160.

### 5.2. Расшифровка (D339)

Файл `ucrypt` (или age), зашифрованный ключу телефона, открывается по проводу:

```
$ unitool crypt decrypt report.pdf.ucrypt -i phone
```

- **Телефон никогда не отдаёт сырой результат операции закрытым ключом.** Сырая RSA над
  произвольными байтами — это и есть подпись: компьютер выдал бы «расшифровку» за вход по SSH в
  обход листа. Сырой X25519 над выбранной точкой — лишний оракул.
- Поэтому телефон получает **запись получателя целиком** (HPKE-обёртку `ucrypt` или стансу age) и
  снимает её сам: X25519 + HPKE open или RSA + OAEP. Наружу уходит только ключ файла (32 байта) и
  только если тег или паддинг сошлись. Содержимое файла расшифровывает уже компьютер.
- Перед этим — лист «Расшифровать файл для laptop · ucrypt · 100 КБ · ключ home» и биометрия.
  После вскрытия телефон проверяет HMAC заголовка ключом файла и не отдаёт ключ, если заголовок
  подменён.
- Запрос идёт отдельной службой канала `decrypt` (07 §2), а не через ssh-agent: в протоколе
  ssh-agent расшифровки нет, и `ssh` к ней отношения не имеет.
- Закрытый шаг на телефоне уже есть: X25519-близнец Ed25519 на Android, ключ уровня 2 на iPhone,
  `SshDecryptionKey` из crypt/03 §1.3. Ключ P-256 в Secure Enclave получателем `ucrypt` 1.0 быть
  не может (crypt D301) — вопрос 159.

## 6. Один владелец кабеля (D340)

Аксессуар AOA занимает интерфейс USB целиком: с телефоном говорит ровно один процесс. Это
демон `unitool link run` (1.1; в 1.0 — `unitool agent run`).
- Остальные команды `unitool` идут к телефону через его сокет `link.sock` (07 §3) и открывают
  потоки к службам телефона:
  - `ssh-agent` — ключи и подпись SSHSIG тем же протоколом, что у `ssh`;
  - `keys` — список с подробностями: телефон, уровень хранения, кабель или кэш, что ключ умеет;
  - `decrypt` — §5.2.
- Агент не запущен → команда сама запускает его в фоне и подключается, как `gpg-agent`.
  `UNITOOL_NO_AUTOSTART=1` это выключает. С юнитом systemd (03 §1.2) агент и так работает.
- Сокет в каталоге 0700 пользователя — те же права, что у сокета `ssh-agent`.

## 7. Что меняется на телефоне (D341)

- **Видно всё** (меняет D311 и D313). Сопряжённый компьютер видит открытые ключи **всех** ключей
  связки: открытый ключ не секрет. Выбора «какие ключи видит компьютер» при сопряжении больше нет.
- Пользоваться можно любым ключом, но каждая операция — лист и биометрия, как и было.
- Кому нужно спрятать ключ от компьютеров совсем — переключатель «Только на этом телефоне» в
  карточке ключа (вопрос 158).
- Службы `keys` и `decrypt` в реестре `services/phone-link` (07 §6). У листа появляется
  вид «Расшифровать файл». В журнале — операция `AgentDecrypt`: компьютер, ключ, размер, итог.
- В `WELCOME` (02 §5) уходят все ключи с уровнем хранения и тем, что каждый умеет.

## 8. Где код, порядок, оценка (D342)

| Где | Что |
|---|---|
| `unitool-kit` → `kit.keys` | `KeyRef` (разбор ссылок), `KeyEntry` (ключ, источник, уровень, что умеет) |
| `unitool-cli/keys` (новый модуль) | источники (телефон через сокет агента, GitHub через `Http`, файлы, `SSH_AUTH_SOCK`), `KeyOps.sign/decrypt`, общий шаг меню, автозапуск агента |
| `unitool-cli/apps/keys` | `unitool keys`, `unitool keys show` |
| `unitool-cli/apps/crypt` | `-r`, `-R`, `-i` принимают ссылки; шаг меню — общий |
| `services/ssh` → `RemoteAgent` | все ключи видны, два расширения, лист расшифровки, журнал |

| Что | Когда | Дней |
|---|---|---|
| `kit.keys`, `unitool-cli/keys`, `unitool keys`, автозапуск, `keys@` на телефоне, все ключи видны | вместе с этапом 4–5 v1 (04 §2) | 2 |
| Ссылки и общий шаг меню в `crypt` | когда построен `crypt` (вопросы crypt 139–145) | 1 |
| `decrypt@` на телефоне и в CLI | после `crypt` | 2 |
| `unitool sign` / `verify` | если вопрос 160 — да | 1 |
| **Итого** | | **≈ 5–6** |

## 9. Решения этой заметки

| № | Решение |
|---|---|
| D335 | Источники ключей CLI: телефон по проводу, GitHub, файл, `SSH_AUTH_SOCK`, строка, отпечаток. Ссылки `phone[:…]`, `gh:LOGIN`, `file:PATH`, `agent` работают везде, где команда берёт ключ (`-r`, `-R`, `-i`, `-k`); разбор — `kit.keys.KeyRef` (§2) |
| D336 | Приложение `unitool keys`: все открытые ключи одним списком с источником, уровнем и честной колонкой «что можно» (`ssh`, `sign`, `encrypt`, `decrypt`). GitHub — только по `gh:LOGIN` (§3) |
| D337 | Общий шаг меню «чьи ключи» в `unitool-cli/keys` для всех приложений; телефон первым; кэш открытых ключей годится для шифрования без кабеля (§4) |
| D338 | Подпись телефоном в CLI — SSHSIG через обычный `SIGN_REQUEST`, проверка `ssh-keygen -Y verify`. git подписывает коммиты ключом телефона уже через агента (§5.1) |
| D339 | Расшифровка по проводу: телефон снимает запись получателя целиком (HPKE / OAEP) и отдаёт только ключ файла после листа и биометрии; сырых операций закрытым ключом наружу нет (§5.2) |
| D340 | (1.1) Кабелем владеет только демон `unitool link run`; остальные команды — через его `link.sock` к службам `ssh-agent`, `keys`, `decrypt`; автозапуск демона (§6, 07 §3) |
| D341 | Телефон показывает сопряжённому компьютеру все открытые ключи (меняет D311, D313); каждая операция — лист и биометрия; ключ можно спрятать переключателем (§7) |
| D342 | Ключи телефона во всём CLI ≈ 5–6 дней: основа вместе с v1, `crypt` и расшифровка — после `crypt` (§8) |
