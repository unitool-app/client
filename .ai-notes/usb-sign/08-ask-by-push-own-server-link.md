## 2. Файлы только внутри Unitool (D352, ответ 161)

| | Где | Кто видит |
|---|---|---|
| Android, все версии | `filesDir/link/from-computer/` и `filesDir/link/to-computer/` во внутренней памяти приложения | только экран файлов Unitool |
| iOS | `Library/Application Support/link/…`, без `UIFileSharingEnabled` и `LSSupportsOpeningDocumentsInPlace` | только экран файлов Unitool. В «Файлах» папки Unitool нет |

- В 1.3 я написал, что на iPhone «выбора нет». Это неверно: выбор есть — показывать ли папку в
  «Файлах». «Только unitool» читаю одинаково для обоих телефонов (вопрос 169).
- Файл выходит наружу только по действию человека на экране файлов, по одному файлу:
  - «Открыть в…»: на Android `ACTION_VIEW` через `FileProvider` с временным правом на этот файл,
    на iOS `UIDocumentInteractionController`;
  - «Поделиться»: системный лист;
  - «Сохранить в…»: на Android системный диалог `ACTION_CREATE_DOCUMENT`, на iOS
    `UIDocumentPickerViewController` для экспорта.
- Что упрощается:
  - MediaStore больше не нужен;
  - пропадает развилка Android 10+ / 7–9, код один для всех версий;
  - разрешений на память не нужно.
- В системные бэкапы файлы не попадают:
  - на Android правила бэкапа уже только из `include` (`backup_rules.xml`,
    `data_extraction_rules.xml`), поэтому `filesDir/link` в Google не уходит;
  - на iOS папка помечается `isExcludedFromBackup`, поэтому её нет в iCloud.
- В бэкап хоста файлы тоже не входят. Он несёт данные приложений (ssh-new D170), а оригиналы
  лежат на компьютере.
- Мини-приложения папку не видят: системный выбор файлов (`services/file-picker`) её не
  показывает. Дверь для мини-приложений — позже, вместе со службами канала для них (07 §6).
- `FileSharer` (`services/share`) принимает только текст. Экран файлов — экран хоста, поэтому он
  вызывает платформу напрямую, контракт не меняется.

## 3. Спрашиваем всегда, вопрос приходит уведомлением (D353, D354, ответ 162)

**D353.** Каждую пачку входящих файлов телефон показывает человеку. Переключателя «Принимать без
вопроса» нет. Бэкап, подпись и расшифровка и так спрашивают каждый раз (лист и биометрия).
Отправку с телефона на компьютер нажимает сам человек, поэтому компьютер ничего не спрашивает
(07 §4.2, без изменений).

**D354.** Как вопрос доходит до человека:

| Состояние | iPhone | Android |
|---|---|---|
| Unitool на экране | лист сразу | лист сразу |
| Unitool в фоне, канал есть | не бывает: в фоне iPhone канал не держит (D321) | уведомление от foreground service, без сервера |
| Канала нет, телефон на кабеле | пуш через наш сервер (05) | пуш через наш сервер (05) |

Для человека это одно и то же уведомление. Нажатие открывает Unitool, компьютер подключается, и
открывается лист с подробностями: [Отклонить] [Принять].

**Что в пуше.** Только вид запроса и метка компьютера, то есть то, что сервер и так знает
(05 §3). Имена и размеры файлов, имена серверов SSH, отпечатки в пуш не кладём, иначе их увидят
сервер, Google и Apple. Поддельный пуш тогда показал бы неправду. Подробности есть только на
листе, а на лист попадает только то, что пришло по Noise от сопряжённого компьютера.

| `kind` | Уведомление |
|---|---|
| `ssh-sign` | «laptop · запрос подписи SSH» |
| `decrypt` | «laptop · расшифровать файл» |
| `files` | «laptop · файлы для вас» |
| `backup` | «laptop · бэкап» |

- Локальное уведомление на Android может показать больше: имена файлов и размер. Его строит
  Unitool из данных канала, а не сервер.
- Кнопок «Принять» в самом уведомлении пока нет:
  - на iPhone передача всё равно идёт, только пока Unitool на экране (07 §6);
  - подпись требует биометрию на листе.

  Подробности в пуше с шифрованием насквозь и кнопками — вопрос 168.
- Защита от «засыпать вопросами». Так взломали Uber в 2022 году: слали запросы MFA, пока человек
  не нажал «да».
  - Сервер пропускает не больше одного вопроса в 10 с на пару «компьютер — вид» (05 §2).
  - Телефон после трёх отказов подряд от одного компьютера за 10 минут замолкает для него на
    10 минут. В карточке компьютера тогда видна кнопка «Отключить laptop».

## 4. Свой сервер (D355, ответ 162)

Что сервер делает для link:

| Что | Зачем |
|---|---|
| Личность компьютера (`POST /v1/clients`) и грант телефона по QR | знать, кто с кем сопряжён (05 §6) |
| Адрес пуша телефона, рассылка через `push-gateway` | вопросы пушем (§3) |
| `POST /v1/wakes` с `kind` из §3 | будильник для всех служб (05 §2) |
| Следующим шагом — труба между компьютером и телефоном | связь без кабеля (§5) |

Всё, кроме последней строки, уже спроектировано в remote-progress (idea/08,
`.ai-notes/remote-progress`):
- личности клиентов;
- пейринг по QR;
- токены устройств `dt_…`;
- рассылка через `push-gateway`;
- пределы и отзыв гранта.

Если делать два сервера, будут две копии одних и тех же личностей и QR, а человеку придётся
сопрягать дважды. Предложение: один сервер Unitool, в котором remote-progress — первая служба, а
link — вторая (вопрос 166, заменяет 156).

Сервер ещё не построен. Его ждут вопросы 114–117: домен, сервисный аккаунт Firebase
`unitool-b1529`, npm и репозиторий.

Чего сервер не получает никогда:
- закрытых ключей;
- содержимого и имён файлов;
- содержимого бэкапа;
- данных подписи.

## 5. Связь без кабеля: сервер как ещё одна труба (D356, вопрос 167)

Ответ 165 «то, что по проводу, не так важно» и «сервер, который будет подключать» ведут сюда.
Канал уже не доверяет трубе (02 §3): Noise `KK` заканчивается на телефоне и в демоне. Значит,
сервер может быть просто ещё одной трубой:

```
unitool link run ──TLS──► сервер ◄──TLS── Unitool на телефоне
       └──────────── Noise KK насквозь ───────────┘
```

- Обе стороны подключаются к серверу сами. Сервер соединяет два подключения по id пары и
  перекладывает байты.
- Обе стороны сервер проверяет (секрет компьютера, токен устройства), чтобы чужие не гоняли через
  него трафик. Кто на другом конце, проверяет Noise.
- Демон выбирает трубу сам: кабель, если он есть, иначе сервер, если он включён для этого
  компьютера.
- iPhone: ограничение то же, что с кабелем. Unitool держит подключение, только пока он на
  экране, а будит его пуш (§3).
- Android: подключается после пуша. Длинную передачу держит foreground service `dataSync`; на
  Android 15 он ограничен 6 часами в сутки.
- CLI: HTTP в нативном бинаре идёт через libcurl по `dlopen` (crypt, вопрос 143). WebSocket в
  libcurl появился в 7.86 и до 8.11 был экспериментальным, а в Ubuntu 22.04 стоит 7.81. Поэтому
  труба CLI — скорее два обычных потока HTTPS: долгий `GET` на приём и `POST` на отправку.
  Проверяет разведка S8.

Что меняется в безопасности:

| С кабелем | Через сервер |
|---|---|
| Компьютер видит ключ, только пока телефон на кабеле (D318). Без кабеля не будим (D332) | Компьютер может спросить, когда телефон в кармане в другом городе. Лист и биометрия остаются на каждую операцию, но кабель больше не доказывает, что человек сидит за этим компьютером |
| Сервер видит метку и время будильника (D330) | Сервер видит ещё, кто с кем говорит, когда и сколько байт. Содержимого не видит |
| Трафик идёт по USB | Трафик идёт через наш сервер: файл в 1 ГБ — это 1 ГБ на сервере туда и 1 ГБ обратно |

Предложение:
- в карточке компьютера переключатель «Через интернет», по умолчанию выключен;
- на листе маршрут: «по кабелю» или «через интернет»;
- предел размера файла через сервер — 100 МБ;
- делать после пуша (05): тот же сервер, те же личности, тот же пуш.

Сопряжение через сервер (QR и так несёт psk, 02 §4) позволило бы обойтись без кабеля вовсе.
Это следующий шаг после самой трубы и решается отдельно.

## 6. Имя: link (D357, ответ 165)

| Что | Было (1.3) | Стало |
|---|---|---|
| Экран на телефоне | «Компьютер по проводу» | «Link» — рабочее имя, в «Настройках»; ссылка с экрана «SSH-ключи» остаётся |
| Строка аксессуара AOA (model) | `Unitool Agent` | `Unitool Link`. Её человек видит в системном диалоге «Открыть Unitool для …?» |
| Команды, сокеты, код | `unitool link …`, `agent.sock`, `link.sock`, `kit.link`, `services/phone-link` | без изменений |
| Порт на iPhone, префикс QR | `47370`, `unitool-pair:1:` | без изменений |

Окончательное имя для людей придумает владелец. Тогда меняются только строки экрана, код и
команды остаются.
