## 1. Desktop: приложение `agent` в CLI (D317)

Не отдельная программа `iphone-ssh-agent`, а приложение нашего CLI (`unitool-cli/apps/agent`): тот
же нативный бинарь, тот же каркас команд, тот же kit. Один код с телефоном — правило cli D280.

**Ответ владельца (146): «это же будет делать CLI unitool».** Значит, агент работает на тех
платформах, под которые собран CLI, — сейчас это Linux (`linuxX64`). Когда CLI получит macOS,
агенту понадобится своя платформенная часть (§1.7), и это работа плана CLI, а не этого (D326).

### 1.1. Команды

| Команда | Что делает |
|---|---|
| `unitool agent pair` | QR в терминале, ждёт телефон на кабеле, сопрягает (02 §4) |
| `unitool agent devices` | сопряжённые телефоны: подключён ли кабелем, есть ли канал, какая труба, когда виделись |
| `unitool agent keys` | ключи телефона: тип, отпечаток, уровень хранения, комментарий. Короткая форма `unitool keys phone` — все источники ключей в 06 §3 |
| `unitool agent public-key [N]` | строка `authorized_keys` — для `~/.ssh/authorized_keys` на сервере |
| `unitool agent run` | агент на переднем плане; печатает `SSH_AUTH_SOCK=…` |
| `unitool agent forget PHONE` | забыть телефон |

```console
$ unitool agent devices
iPhone Ивана
  cable: connected (usbmux)   link: up   paired: 2026-10-06
$ unitool agent public-key
ecdsa-sha2-nistp256 AAAAE2VjZHNhLXNoYTItbmlzdHAyNTY… work (secure-enclave)
```

Все тексты CLI — английские (cli D294).

### 1.2. Сокет и настройка OpenSSH

- Linux: `$XDG_RUNTIME_DIR/unitool/agent.sock`, каталог 0700. macOS: `~/.unitool/agent.sock`.
- Подключение — одной строкой в `~/.ssh/config`:

  ```
  Host *
      IdentityAgent ${XDG_RUNTIME_DIR}/unitool/agent.sock
  ```

  или `export SSH_AUTH_SOCK=…` для `ssh-add -L` и старых программ.
- Фоном агент сам не уходит. Запуск при входе — пользовательский юнит systemd, его текст печатает
  `unitool agent run --print-systemd-unit`. На macOS позже — `launchd`.

### 1.3. Подсказка о клиенте (не проверено)

Linux: `SO_PEERCRED` у принятого соединения → pid → `/proc/<pid>/cmdline` и `/proc/<pid>/exe`.
Если клиент — `ssh`, запущенный `git`, берётся и родитель: «`git push` → `ssh git@github.com`».
macOS: `LOCAL_PEERPID` + `proc_pidpath`. Подсказка уходит в `OPEN` и на листе подписана как «не
проверено» (02 §7.2).

### 1.4. Ключ есть, пока телефон воткнут (D318)

Как у YubiKey: кабель вставлен — ключ виден, вынут — ключа нет.
- Телефон подключён кабелем и канал открыт → `REQUEST_IDENTITIES` идёт на телефон.
- Подключён кабелем, но канала нет (iPhone: Unitool не открыт) → ответ из кэша открытых ключей.
  `ssh` выбирает ключ и шлёт `SIGN_REQUEST`, а агент зовёт человека (§1.5).
- Не подключён → пустой список: `ssh` сразу переходит к другим ключам и не ждёт.

«Подключён» — по списку трубы: UDID в `ListDevices` usbmuxd, серийный номер устройства USB для AOA.
Идентификатор запоминается при сопряжении.

### 1.5. Ожидание телефона

`SIGN_REQUEST` без канала:
1. агент показывает уведомление на desktop: «Откройте Unitool на телефоне: ssh ждёт подпись» —
   `notify-send` на Linux, `osascript` на macOS, если они есть. После заметки 05 — ещё и
   пуш-будильник на телефон;
2. ждёт канал до 30 с (вопрос 153), переподключаясь раз в секунду;
3. канал появился → открывает поток, пересылает запомненные `session-bind` и сам запрос;
4. не появился → `FAILURE`, `ssh` идёт дальше.

### 1.6. Как устроен процесс

- Один поток, цикл `poll()`: слушающий сокет, клиенты, трубы, управляющий сокет usbmuxd, таймеры.
  Каркас CLI без зависимостей (cli D291), coroutines нет — и не нужны.
- Код канала из `kit.link` без ввода-вывода (02 §5): цикл кормит его байтами и пишет то, что он
  вернул.
- Нативные вызовы: сокеты POSIX, `ioctl` usbfs для AOA (01 §3), `/proc`. Новых библиотек нет:
  бинарь по-прежнему зависит только от glibc. libusb не нужен: на Linux usbfs проще, чем `dlopen`.
- usbmuxd — свой клиент на ~200 строк: заголовок 16 байт и XML plist из трёх сообщений
  (`ListDevices`, `Listen`, `Connect`), 01 §2.

### 1.7. Модули

| Где | Что |
|---|---|
| `unitool-kit` → `kit.link` | Noise (`KK`, `XXpsk3`), кадры, сообщения канала, ретранслятор ssh-agent без ввода-вывода, кэш ключей |
| `unitool-cli/apps/agent` commonMain | команды, состояние клиентов, правила §1.4–§1.5, хранение `~/.config/unitool/agent/` |
| `unitool-cli/apps/agent` linuxX64Main | сокет, `poll`, `SO_PEERCRED`, usbmuxd, usbfs (AOA), `notify-send` |
| `macosArm64Main` — когда CLI получит macOS (D326) | то же через IOKit, `LOCAL_PEERPID`, `osascript` |

## 2. Телефон: мини-приложение «Подпись для компьютера» (D319)

### 2.1. Где код

Агент — хостовый, его нет в реестре сервисов (ssh-new D151): обычному приложению сырая подпись
не выдаётся. Поэтому мини-приложение — экран хоста, как «SSH-ключи», а не приложение Superizer.
**Superizer не меняется и не выпускается.**

| Где | Что |
|---|---|
| `services/ssh` → `agent/RemoteAgent.kt` | политика компьютера (02 §6) |
| `services/ssh` → `agent/SignRequestView.kt` | разбор данных подписи и проверка `session-bind` (02 §7) |
| `services/ssh` → `UseReason` | новое поле `agent: AgentContext?` — компьютер, пользователь, сервер, подсказка |
| новый `services/phone-link` commonMain | связка «труба → `kit.link` → `RemoteAgent`», список компьютеров, список серверов |
| `services/phone-link` androidMain | аксессуар AOA, foreground service |
| `services/phone-link` iosMain | слушатель на `127.0.0.1` |
| `composeApp` | экраны «Компьютеры», карточка компьютера, лист запроса, «Серверы», строки (ru/en) |

### 2.2. Экраны

```
┌ Подпись для компьютера ─────────────────┐
│ laptop            ● подключён (кабель)  │
│   последняя подпись: 5 мин назад        │
│ desktop-office    ○ не подключён        │
│                                         │
│ [+ Добавить компьютер (QR)]             │
│ Серверы, которые знает телефон  ›       │
└─────────────────────────────────────────┘

┌ Вход по SSH ────────────────────────────┐
│ Компьютер   laptop               ✓      │
│ Пользователь deploy              ✓ подп.│
│ Сервер      prod                 ✓      │
│             SHA256:Xy3…  (закреплён)    │
│ Ключ        work · Secure Enclave       │
│ Компьютер сообщает: ssh deploy@prod     │
│                      (не проверено)     │
│                                         │
│  [ Отклонить ]          [ Подписать ]   │
└─────────────────────────────────────────┘
        «Подписать» → Face ID / отпечаток
```

Системный промпт повторяет главное одной строкой: «Вход deploy → prod с laptop». Это
`UseReason` → `PromptText` (ssh-new/01 §5.2), только с новым полем.

### 2.3. Android (D320)

- Манифест:
  - `<uses-feature android:name="android.hardware.usb.accessory" android:required="false"/>`;
  - активити с `USB_ACCESSORY_ATTACHED` и `accessory_filter.xml` (manufacturer `m42.cx`, model
    `Unitool Link`);
  - сервис `foregroundServiceType="connectedDevice"`, разрешения `FOREGROUND_SERVICE`,
    `FOREGROUND_SERVICE_CONNECTED_DEVICE`, `POST_NOTIFICATIONS`. Предусловие типа — разрешение на
    аксессуар, оно уже есть после системного диалога. Декларация типа в Play Console — при
    выпуске (вопрос 154).
- Поток событий: кабель → desktop переключает телефон в режим аксессуара → система спрашивает
  «Открыть Unitool для Unitool Link?» (можно «всегда») → активити запускает foreground service →
  сервис открывает аксессуар и держит канал, пока кабель вставлен. Уведомление сервиса: «laptop
  подключён · ключей: 1».
- Запрос:
  - Unitool на экране → лист сразу;
  - иначе — уведомление высокой важности «Запрос подписи SSH» → нажатие → активити → лист →
    `BiometricPrompt`. Активити из фона сами не запускаются: ограничения Android 10+ это
    запрещают, и уведомление — разрешённый путь (01 §3);
  - телефон заблокирован → на экране блокировки уведомление без подробностей, после разблокировки
    — подробности. Ключ чипа заблокированный телефон не подпишет всё равно
    (`setUnlockedDeviceRequired`).
- Android 16 с Advanced Protection не открывает соединение по USB, пока телефон заблокирован:
  сначала разблокировать, потом вставить кабель. Это надо сказать в подсказке «Компьютер не
  видит телефон».

### 2.4. iOS (D321)

- Экран «Подпись для компьютера» открыт и приложение активно → слушатель на `127.0.0.1:<порт>`
  (сокеты POSIX из Kotlin/Native). Порт фиксированный (вопрос 150).
- Пока экран открыт и компьютер подключён — `isIdleTimerDisabled = true`: экран не гаснет, телефон
  на кабеле и заряжается.
- Приложение уходит в фон → слушатель и канал закрываются сразу, лист отменяется. Вернулось →
  слушатель снова открыт, desktop переподключается сам (§1.5). Следующий шаг после v1 —
  пуш-будильник: уведомление открывает этот экран, и компьютер подключается по кабелю (05).
- Face ID спрашивает сам Secure Enclave при `SecKeyCreateSignature` — так уже устроен
  `SecureEnclaveBackend`. Нужен только новый текст причины.
- Разрешение «Локальная сеть» не нужно: только приём на loopback (01 §2.1).
- Если компьютер не видит iPhone: телефон разблокирован? доверяет этому компьютеру? Unitool
  открыт? — три строки подсказки на экране и в `unitool agent devices`.

### 2.5. Какие ключи видит компьютер

(1.2) Все ключи связки (06 §7, D341), кроме спрятанных переключателем «Только на этом телефоне». В
списке у каждого виден уровень:
- уровень 1 (чип, ключ не выходит никогда);
- уровень 2 (запечатан чипом, на миг в памяти телефона) — с надписью;
- уровень 3 (только пароль) — промпт попросит пароль ключа на телефоне.

Ключи-однодневки, добавленные через `ssh-add` в агент телефона, компьютеру не видны.

### 2.6. Где вход в мини-приложение (вопрос 149)

Предложение 1.0: строка «Подпись для компьютера» на экране «SSH-ключи» (он уже открывается кодом
`{ssh-keys}`) и карточка ключа «Виден компьютерам: laptop». Отдельного кода и плитки на Home в v1
нет.

**(1.3)** Файлы и бэкап нужны не только владельцам SSH-ключей: экран «Компьютер по проводу» —
из «Настроек», а с экрана «SSH-ключи» на него ведёт ссылка (07 §6, вопрос 165).

**(1.4)** Ответ 165: экран называется «Link» (рабочее имя), вход тот же (08 §6, D357).

## 3. Чего в v1 нет (D322)

- Windows: OpenSSH там говорит с агентом через именованный канал `\\.\pipe\openssh-ssh-agent`.
- macOS — вместе с CLI (D326).
- Труба по локальной сети и Bluetooth (01 §5).
- Пуш-будильник — следующий шаг сразу после v1, заметка 05 (ответ 148).
- adb (ответ 147).
- «Окно доверия»: одна биометрия на N минут для одного компьютера (вопрос 152).
- Несколько телефонов одновременно: сопрячь можно несколько, но канал в v1 открыт с первым
  подключённым.
- Ограничения `ssh-add -h` (`restrict-destination-v00@openssh.com`): ключами управляет телефон.
- Сертификаты SSH и ключи FIDO `sk-*`.
