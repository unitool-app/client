# 05 — пуш-будильник: компьютер будит телефон, потом подключается по кабелю

> **Версия:** 1.2 · **Дата:** 2026-10-06 · Решения D328–D334 · **Статус:** план, после v1
>
> 1.1 — команды переименованы по 07 §3: демон `unitool link run`, сопряжение `unitool link pair`.
> 1.2 — ответ 162 (08 §3–§4): будильник зовёт человека для всех служб, не только для подписи
> (`kind`: `ssh-sign`, `decrypt`, `files`, `backup`); сервер — наш сервер Unitool, remote-progress —
> его первая служба (вопрос 166). Экран — «Link» (D357).
>
> Ответ владельца на вопрос 148: «да, но надо сразу записать, что будем делать — через пуш
> запрос, то есть мы коннектимся к устройству». В v1 iPhone подписывает, только когда Unitool
> открыт (01 §2.4). Следующий шаг — эта заметка.

## 1. Идея

Пуш не везёт запрос подписи. Он только будит телефон: человек нажимает уведомление, Unitool
открывается на экране «Подпись для компьютера», слушатель поднимается, и компьютер **сам
подключается к телефону по кабелю** — дальше всё как в v1.

```
ssh ──► unitool link run: SIGN_REQUEST; телефон на кабеле, канала нет
          │ 1. POST /v1/wakes {targets: [dt_…], kind: "ssh-sign"}    ── HTTPS ──► сервер
          │                                                              │ 2. FCM → APNs / Android
          │                                                              ▼
          │                                     телефон: «Запрос подписи SSH · laptop»
          │                                     3. нажатие → Unitool → экран подписи
          │                                        слушатель на 127.0.0.1 поднят
          │ 4. опрос usbmuxd раз в секунду → Connect → Noise_KK
          │ 5. OPEN, session-bind, SIGN_REQUEST ──────────► лист → Face ID → подпись
ssh ◄──── SIGN_RESPONSE
```

Так уже устроена мысль idea/01: пуш — только «тычок», данные идут своим путём. И правило D25
остаётся: пуш ничего не открывает.

## 2. Почему нужен сервер (D329)

Отправить пуш можно только с серверным ключом: сервисным аккаунтом Firebase для FCM или ключом
APNs. Класть такой ключ на компьютер нельзя: с ним любой шлёт пуши всем установкам Unitool.
Значит, путь — через сервер.

Сервер уже спроектирован: remote-progress (idea/08, `.ai-notes/remote-progress`). В нём есть
почти всё нужное:
- личность клиента (CLI) и её секрет;
- пейринг клиента с телефоном по QR и токен устройства `dt_…`;
- адрес пуша телефона (`push-address`, шаг 6 задания) и рассыльщик через `push-gateway`;
- пределы, отзыв гранта с телефона, `mute`.

Добавляется одна ручка и один вид пуша:

| Метод | Путь | Тело → ответ |
|---|---|---|
| POST | `/v1/wakes` | `{targets: ["dt_…"], kind: "ssh-sign"}` → `202 {targets: [{deviceToken, result}]}` |

- В «Входящие» мини-приложения прогресса будильник **не попадает**: это не уведомление о
  событии, а вызов.
- Предел — один будильник на пару «клиент — телефон» в 10 с. Лишние сервер отбрасывает, отвечая
  `202`.

## 3. Что видят сервер, Google и Apple (D330)

| Кто | Видит | Не видит |
|---|---|---|
| Сервер | клиента (метку компьютера), телефон, время вызова | пользователя, сервер SSH, ключ, данные подписи |
| FCM / APNs | текст уведомления и время | то же |
| Подделавший пуш | — | может только открыть экран. Подпись требует сопряжённый компьютер на кабеле (Noise KK), лист и биометрию |

Взлом сервера даёт лишние уведомления, но не подписи.

## 4. Форма пуша (D331)

| Поле | Значение |
|---|---|
| Заголовок | «Запрос подписи SSH» |
| Тело | метка компьютера, которую сервер уже знает: «laptop» |
| `data` | `{"v":1,"kind":"ssh-sign"}`; (1.2) `kind` — также `decrypt`, `files`, `backup`, заголовки в 08 §3 |
| `link` | `unitool://host/ssh-sign` — экран «Подпись для компьютера» |
| Срок жизни | 60 с (`ttl`, `apns-expiration`): старый будильник бесполезен |
| Схлопывание | `tag` и `apns-collapse-id` = id клиента: десять запросов подряд — одно уведомление |
| Android | канал `unitool.ssh`, высокая важность, `priority: high` |
| iOS | `interruption-level: time-sensitive`, проходит сквозь «Фокус» (вопрос 155); без него `active` |

Экран подписи, открывшись, снимает это уведомление из шторки.

## 5. Когда компьютер будит (D332)

- Пришёл `SIGN_REQUEST`, телефон на кабеле, канала нет, у телефона есть токен сервера → будильник
  и уведомление на самом компьютере, ожидание (03 §1.5).
- **(1.2)** То же для любой службы, которой нужен человек: `decrypt`, `files.put`,
  `backup.*` (08 §3, D354). Ссылка ведёт на экран «Link», лист открывается после подключения.
- Телефона на кабеле нет → не будим: ключа в списке нет вовсе (D318). Будить телефон в кармане ради
  входа, который всё равно не пройдёт по кабелю, бессмысленно.
- Android: foreground service держит канал, пока кабель вставлен, и будильник почти не нужен. Он
  срабатывает, только если сервис убит (агрессивная экономия батареи у некоторых
  производителей). Правило одно для обеих платформ.

## 6. Сопряжение — один QR (D333)

`unitool link pair` показывает один QR:

```
unitool-pair:1:<base64url(static_pub ‖ psk)>;name=laptop;srv=<url>;t=<pairingToken>
```

- Телефон делает две вещи: сопряжение Noise по кабелю (02 §4) и подтверждение гранта на сервере
  — тот же запрос, что у пейринга прогресса.
- Компьютер забирает токен `dt_…` опросом и кладёт в `phones.json` рядом с ключом Noise телефона.
- `unitool link pair --no-push` — только сопряжение по кабелю, без сервера.
- В карточке компьютера на телефоне — переключатель «Будить пушем». Выключить → телефон отзывает
  грант на сервере (`DELETE /v1/me/clients/{clientId}`, remote-progress/01 §6).

Компьютеру нужна личность на сервере. Её создаёт сам демон `unitool link run` при первом сопряжении с
пушем (`POST /v1/clients`), секрет лежит в `~/.config/unitool/agent/` (0600).

## 7. Что для этого нужно

| Что | Где | Зависит от |
|---|---|---|
| Сервер remote-progress: личности, пейринг, рассыльщик (шаги 0–3) | `/prj/unitool-progress` | ревью задания, вопросы 114–117 (домен, сервисный аккаунт Firebase `unitool-b1529`, npm, репозиторий) |
| `push-address` в хосте Unitool (шаг 6 задания) | Unitool | то же |
| Пуш на iOS вообще | Firebase: приложение iOS в проекте `unitool-b1529`, ключ APNs | владелец (ios/01, пункт «Firebase, проект `unitool-b1529`») |
| HTTP в нативном бинаре CLI | `unitool-cli` | вопрос 143 (crypt): libcurl через `dlopen` |
| `/v1/wakes` | сервер | — |
| Будильник и QR с сервером | `apps/agent` | всё выше |
| Ссылка `unitool://host/ssh-sign`, канал `unitool.ssh`, переключатель | Unitool | — |

## 8. Оценка и порядок (D334)

После v1 и после того, как сервер remote-progress и `push-address` живут:

| Что | Дней |
|---|---|
| `/v1/wakes`, вид пуша, тексты, тесты сервера | 0,5 |
| Клиент сервера в CLI: личность, пейринг, будильник (поверх HTTP из вопроса 143) | 2 |
| Телефон: подтверждение гранта из QR, ссылка, канал, переключатель, снятие уведомления | 1 |
| Сквозная проверка: iPhone в фоне → пуш → вход | 0,5 |
| **Итого** | **≈ 4** |

## 9. Позже

С пушем и сервером в руках остаётся один шаг до входа без кабеля: после пробуждения компьютер
подключается к телефону не по USB, а по локальной сети (01 §5) — тот же канал Noise. Это отдельное
решение, не часть этой заметки.

## 10. Решения этой заметки

| № | Решение |
|---|---|
| D328 | Пуш — только будильник: без данных запроса, ничего не открывает. Запрос и подпись идут по кабелю после того, как человек открыл Unitool; телефон принимает только сопряжённый компьютер (§1) |
| D329 | Путь: `unitool link run` → сервер remote-progress (`POST /v1/wakes`) → `push-gateway` → FCM → APNs / Android. Серверных ключей пуша на компьютере нет. Будильник не попадает во «Входящие», предел — один в 10 с (§2) |
| D330 | Сервер, Google и Apple видят метку компьютера и время, но не пользователя, сервер SSH и данные. Взлом сервера даёт только лишние уведомления (§3) |
| D331 | Форма: «Запрос подписи SSH» + метка, ссылка `unitool://host/ssh-sign`, срок 60 с, схлопывание по компьютеру, Android — канал `unitool.ssh`, iOS — `time-sensitive` (вопрос 155) (§4) |
| D332 | Будить, когда есть `SIGN_REQUEST`, телефон на кабеле и нет канала. Без кабеля не будить. Правило одно для iOS и Android (§5) |
| D333 | Один QR на сопряжение по кабелю и грант на сервере; `--no-push` для одного кабеля; переключатель «Будить пушем» на телефоне отзывает грант (§6) |
| D334 | Пуш-будильник — после v1 и после сервера remote-progress с `push-address`; ≈ 4 дня (§8) |
