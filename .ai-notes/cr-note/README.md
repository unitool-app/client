## Что сказал владелец (близко к тексту)

> «Давай сделаем новое приложение, спрятанное за промокодом [cr-note]. Оно будет открываться за
> лицом, и при создании будет ещё ставиться пинкод один раз. Открываться только через фейс +
> пинкод, извлекать можно только зашифрованное через openssl или age. Внутри будут записки.
> Тот пинкод, который ввёл, в ту и попал директорию записок. Пинкод 178500 будет стирать все
> записки.»
>
> «278 — да. 279 — там пусть будет показана пустая новая директория. 280 — да, прячь. Сами данные
> должны быть зашифрованы, чтобы тот, у кого есть root-доступ, не мог открыть их. И надо сделать
> экспорт и импорт записок внутри директории. Экспорт — по одной директории.»

## Коротко

1. **`cr-note`** — скрытое приложение, как `cr-restore`: открывается только точным промокодом
   `[cr-note]` (или `{cr-note}`), на один визит. Нет ни в каталоге, ни на Home.
2. **Вход — всегда два шага: лицо, затем PIN** (6 цифр). Код-пароль телефона не открывает.
3. **Первый вход — создание:** лицо, потом PIN дважды. Это и есть «пинкод один раз».
4. **Каждый PIN — своя директория записок.** Ввёл PIN — попал в его директорию. Неверного PIN не
   бывает: незнакомый PIN открывает пустую директорию (ответ на 278).
5. **PIN `178500` стирает всё** — все директории всех PIN, без возврата — и показывает пустую
   новую директорию, как любой незнакомый PIN (D655).
6. **Root не откроет:** на диске только шифр, ключ — в чипе и только после лица; сколько
   директорий, не видно — среди них ложные файлы (D662, D664).
7. **Наружу — только зашифрованное:** экспорт директории целиком в age или `openssl enc`. Ни
   копирования текста, ни «Поделиться» открытым текстом, ни скриншотов. **Импорт** — такой же
   файл обратно, в открытую директорию.
8. **Ушёл в фон или минута простоя — приложение закрыто и забыто.** Обратно — снова промокод,
   лицо, PIN.

## Решения

### Приложение

- **D649. Имя и вид.**
  - `apps/cr-note`, AppId `cr-note`, пакет `cx.m42.apps.crnote`, `CrNoteApp`.
  - Заголовок — `cr-note` в обоих языках, как у `cr-restore`.
  - Манифест: `secret = true`, `hidden = true`,
    `protection = AppProtection(lock = LockPolicy.Off, secureWindow = true)`.
    Замок хоста не нужен: лицо спрашивает само приложение, и это же лицо открывает ключ (D654).
    Иначе было бы два промпта подряд.
  - Только Android и iOS. На вебе нет (нет чипа), на десктопе — только для тестов с ненастоящим
    ключом.
- **D650. Промокод `[cr-note]` — точный**, как `[ssh-keys]` и `[cr-restore]`. В коде только хеш
  (`scripts/promo-hash.sh`), сам код — в `.secrets/promo-codes.md`.

### Вход

- **D651. Порядок: лицо → PIN.**
  - Лицо первым: оно открывает корневой ключ (D654). Без него PIN нечем проверять и некуда
    вести.
  - Только биометрия: Android `BIOMETRIC_STRONG` без `DEVICE_CREDENTIAL`, iOS
    `.biometryCurrentSet`, без кнопки «Ввести код-пароль».
  - Отменил лицо или не узнало — приложение закрывается.
  - Телефон без биометрии (или она не настроена): промокод принимается так же, как везде, а дальше
    **тихо ничего не происходит** — ни промпта, ни сообщения, приложение сразу закрывается и
    возвращает туда, откуда пришли (ответ на 284). Со стороны не отличить от «код не сработал
    без объяснений»; что приложение есть, экран не выдаёт. Ключ чипа и файлы не создаются.
- **D652. Создание — один раз.**
  - Первый вход: «Придумайте PIN» → «Повторите PIN». Создаётся корневой ключ (D654).
  - PIN — ровно 6 цифр. `178500` поставить нельзя.
  - Сменить PIN нельзя: смены нет, есть только другой PIN = другая директория.
  - Создание бывает только при самом первом входе. После `178500` его нет (D655).
- **D653. PIN выбирает директорию.**
  - Директория — это `slot = HKDF(R, "cr-note slot" ‖ PIN)`, ключ записок —
    `K = HKDF(R, "cr-note key" ‖ PIN)`.
  - Знакомый PIN — его записки. Незнакомый — пустая директория, в которой можно писать, без слов
    «неверный PIN» (ответ на 278). PIN при создании — просто первый из них.
  - Пустая директория на диск не пишется, пока в ней не сохранена первая записка. Опечатка в PIN
    ничего не оставляет.
  - Счётчика попыток нет: с лицом перебор PIN ничего не «ломает», он только открывает пустые
    директории. Без лица перебирать нечего — нет R.
- **D654. Ключи.**
  - **R** — 32 случайных байта, корень всего. Хранится зашифрованным ключом чипа:
    - Android — AES-GCM в Keystore, `setUserAuthenticationRequired(true)`,
      `BIOMETRIC_STRONG`, `setInvalidatedByBiometricEnrollment(true)`, `CryptoObject` в промпте;
    - iOS — Secure Enclave P-256 с `.biometryCurrentSet` + `.privateKeyUsage`, тот же `LAContext`.
  - Это новый `services/vault` `BiometricKey`: `create()`, `unlock(prompt): ByteArray`,
    `destroy()`. Это тот же «охраняемый ярус» vault-auth (D569, D570), но без слота
    восстановления и только для одного приложения. Если vault-auth построят, `cr-note`
    переходит на него.
  - Медленный KDF для PIN не нужен: R 256 бит и без лица из чипа не выходит, поэтому файлы на
    диске без телефона и лица не перебрать.
  - R живёт только в памяти, пока приложение открыто; при закрытии `fill(0)`.
- **D655. `178500` стирает всё.**
  - После лица ввели `178500`:
    1. `BiometricKey.destroy()` — ключ чипа удалён, всё, что было, уже не расшифровать;
    2. удаляются все файлы директорий, настоящие и ложные;
    3. молча создаётся новый ключ чипа и новый R (лицо только что приложено, второй промпт не
       нужен: на Android ключ создаётся с `setUserAuthenticationParameters(10 с, BIOMETRIC_STRONG)`,
       на iOS шифрование открытым ключом Enclave лица не требует);
    4. кладутся новые ложные файлы (D664) — на диске то же, что у неначатого приложения с записками.
  - На экране — **пустая новая директория**, как после любого незнакомого PIN (ответ на 279). Ни
    «Придумайте PIN», ни «Всё стёрто».
  - В ней можно писать: это обычная директория PIN `178500`. Следующий `178500` сотрёт и её.
  - Отменить нельзя, подтверждения нет. Длится меньше секунды, чтобы не выдать себя паузой.
- **D656. Сменили набор лиц/пальцев — записок больше нет.**
  - Это прямое следствие `.biometryCurrentSet` / `InvalidatedByBiometricEnrollment`: ключ чипа
    исчезает, R не открыть. Закрывает «знаю код телефона → добавил своё лицо → открыл».
  - Слота восстановления нет. При следующем входе — «Записки недоступны: изменилась биометрия»
    и создание заново (ответ на 281: так и оставить).

### Записки

- **D657. Минимум, как у остальных маленьких приложений.**
  - Директория — список: первая строка как заголовок, дата изменения. «+» — новая.
  - Записка — простой текст. Сохраняется сама (через полсекунды после ввода), удаление — с
    подтверждением.
  - Как это лежит на диске — D662.
- **D658. Не в бэкап.** Данные `cr-note` не попадают в бэкап хоста. Иначе бэкап — вторая копия,
  которую не стирает ни `178500`, ни смена биометрии, и её ключ уже не тот. Для этого нужен флаг в
  манифесте (вроде `backup = false`), если в Superizer его нет — правка контракта (ответ на 282: не в бэкап).
- **D662. Данные зашифрованы, root их не откроет** (владелец, 0.2).
  - На диске нет ничего открытого: ни текста, ни заголовков, ни дат, ни числа записок, ни PIN.
  - Директория — один файл `cr-note/<slot в hex>`, содержимое — `nonce ‖ AesGcm(K, json всех
    записок)`. AAD — `slot`, чтобы файл нельзя было подложить под другой PIN.
  - Длина добита до кратной 16 KiB случайными байтами под шифром — объём не виден.
  - Новый nonce при каждой записи, запись через временный файл и переименование.
  - K = HKDF(R, PIN), R = 32 байта, лежит только завёрнутым ключом чипа (D654). Ключ чипа
    **не выдаёт себя наружу и работает только после биометрии внутри TEE / Secure Enclave**:
    root-доступ к файлам и памяти закрытого приложения даёт шифр и завёрнутый R, но не ключ.
    Перебирать 10⁶ PIN бесполезно — без R их не с чем сравнить.
  - Пока приложение открыто, R и текст — в памяти процесса; при закрытии `fill(0)` (D659).
  - Своё хранилище приложения байтами, не `runtime.secrets`, не `runtime.storage`-строки: так
    хост ничего не кеширует и не пишет в журнал. Снимка состояния нет (`saveState()` → null).
  - Проверка: тест, что ни один файл `cr-note/` не содержит ни строки записки, ни PIN, ни
    длины, отличной от кратной 16 KiB; тест на Android-эмуляторе, что ключ Keystore отказывает
    без `CryptoObject` с биометрией.
- **D664. Ложные файлы прячут число директорий** (ответ на 280).
  - С самого создания в `cr-note/` лежит 8 файлов случайных байтов той же длины и с именами того
    же вида, что настоящие. Когда настоящих становится столько, что ложных меньше 4, добавляются
    ещё 8.
  - При каждой записи настоящей директории перезаписываются ещё 1–2 случайных ложных файла новыми
    случайными байтами — по сменившимся файлам между двумя снимками не понять, какие настоящие.
  - Ложный файл на чтение — то же, что незнакомый PIN: не расшифровался → пустая директория.
  - Честно: кто снимает диск много раз подряд, видит, что какие-то файлы меняются; какие из них
    настоящие — нет.

- **D659. Закрытие.**
  - Уход в фон → приложение закрыто сразу, без шторки и без отсрочки. secret-return (D620–D623)
    опускает шторку для открытых секретных приложений — `cr-note` надо из этого исключить:
    шторка — это одно лицо, а нужно лицо + PIN.
  - Простой 1 минута → закрыто.
  - При закрытии: R, K, текст записок в памяти — `fill(0)`, поля очищаются.

### Наружу

- **D660. Наружу только зашифрованное; экспорт — одной директорией** (ответ на 285).
  - В тексте записки нельзя копировать и вырезать (своё меню выделения без «Копировать»).
    Вставлять можно.
  - Нет «Поделиться» открытым текстом, нет открытого файла. `secureWindow` закрывает скриншоты,
    запись экрана и миниатюру в недавних.
  - «Экспорт» в меню директории выгружает **всю открытую директорию** одним файлом. Других
    директорий экспорт не видит и не упоминает. Одной записки отдельно нет.
  - Внутри, до шифрования — `cr-note/1` JSON: `{"format":"cr-note/1","notes":[{"text","created",
    "modified"}]}`. Читается и на компьютере после `age -d`.
  - Формат — по умолчанию age паролем:
    - **age**: паролем (`AgeKeys.encryptWithPassphrase`, scrypt) или на ключи — свои SSH-ключи
      телефона, сохранённые чужие ключи, ключи GitHub-пользователя, `age1…` (`Age.encrypt`,
      `AgeKeys.encryptTo`);
    - **openssl**: `openssl enc -aes-256-cbc -pbkdf2 -iter 600000 -salt` с паролем
      (`OpensslEnc.encrypt`); на экране — команда для расшифровки.
  - Пароль экспорта — минимум 12 знаков, генератор `kit.password` рядом.
  - Результат — `FileSaver` («Сохранить как») или «Поделиться» файлом `.age` / `.enc`.
  - Расшифровать можно `cr-restore`, `age -d`, `openssl enc -d …` — проверяется тестом на настоящих
    бинарях, как в cr-restore (D618).
- **D661. Импорт — в открытую директорию** (владелец, 0.2).
  - «Импорт» в меню директории: файл (`FilePicker`) или QR-серия (`scanSeries`), если длинное.
  - Понимает:
    - экспорт `cr-note` в age — паролем, ключом этого телефона (SSH или `age1…`);
    - экспорт `cr-note` в openssl — паролем;
    - любой age/openssl-файл с простым текстом внутри — одной новой записью (ответ на 286).
  - Записки **добавляются** к тем, что есть: совпадающие по тексту и `created` пропускаются, ничего
    не заменяется. Перед добавлением — «Добавить N записок?».
  - Открытый текст (`.txt`) не принимается — внутрь только зашифрованное, как и наружу.
  - Расшифрованное при импорте — только в памяти, сразу пишется шифром директории (D662).
- **D663. Где кнопки.** В директории сверху «⋮»: «Экспорт», «Импорт». Больше в меню ничего нет —
  ни списка директорий, ни «Сменить PIN», ни «Стереть»: о них знает только тот, кто знает.

## Чего это не защищает (честно)

- Кто заставит приложить лицо и назвать PIN — увидит ту директорию, PIN которой назван. Другие
  PIN он не узнает, и сколько их — тоже (D664).
- Root, пока приложение **открыто**, может прочитать память процесса — там открытый текст текущей
  директории и R. Закрытое приложение root не откроет (D662).
- Взлом самого TEE / Secure Enclave — вне того, от чего здесь можно защититься.
- Вредонос внутри процесса после лица и PIN видит открытый текст — как в любом приложении.
- Промокод `[cr-note]` есть в списке для ревьюеров Play / App Store (idea/09, ответ на 124).

- **D665. Свои ложные файлы директории** (уточняет D664). Правило «когда ложных меньше 4, добавить
  8» и «перезаписать 1–2 случайных ложных» выполнить нельзя: ложный файл неотличим от директории
  другого PIN, и перезапись случайного «ложного» стёрла бы чужие записки. Поэтому:
  - при создании — 8–12 ложных файлов (не ровно 8, чтобы число не было константой); их больше
    никто не трогает;
  - директория при первом сохранении заводит себе 1–4 своих ложных файла; их имена лежат внутри её
    шифра; при каждом сохранении перезаписываются 1–2 из них, тем же размером, что сама директория.
  - Честно: тот, кто знает схему и видит N файлов, получает грубую вилку числа директорий (каждая
    — 2–5 файлов сверх стартовых 8–12). Точного числа не видно, и по одному PIN о других не узнать.
- **D666. Android: RSA-OAEP, а не AES** (уточняет D654, D655). Ключ чипа — RSA-2048 в TEE,
  `AUTH_BIOMETRIC_STRONG`, таймаут 0, расшифровка только внутри `BiometricPrompt` с `CryptoObject`.
  Шифрование R — открытой половиной, в процессе, без лица — как ECIES на iOS. Поэтому `178500`
  создаёт новый ключ без окна в 10 с, а ключ не работает ни секунды после разблокировки телефона
  отпечатком. OAEP SHA-256 / MGF1 SHA-1 — единственный OAEP, который расшифровывает любой Keystore.
  Не StrongBox: RSA в нём делается секундами. Только API 30+, как ключи keyring; ниже — «нет биометрии» (D651).
- **D667. `178500`: экран сразу, ключ — за ним** (уточняет D655). Новый R и пустая директория
  `178500` показываются мгновенно; уничтожение ключа чипа, удаление всех файлов, новый ключ, запечатанный
  R и новые ложные файлы идут в очереди диска следом. Пауза на создание ключа не видна.
- **D668. Импорт openssl чужого файла.** Пароль пробуется с нашими параметрами (600 000), затем с
  умолчанием `openssl enc -pbkdf2` (10 000) и со старым `EVP_BytesToKey`. Тест — файл настоящего `openssl`.

Прочее, как построено:
- Без биометрии (`available()` ложно, сервиса нет — веб, десктоп, симулятор iOS без Enclave):
  экземпляр сразу закрывается, ни промпта, ни файлов (D651).
- Первый вход: создаётся ключ, R запечатывается, затем лицо его открывает — так проверяется, что
  ключ работает. Отмена — ключ удаляется, приложение закрыто.
- Ключ чипа пропал, а файл `k` есть (Android выбросил ключ) — то же, что смена биометрии (D656).
- Запись: через 0,5 с после ввода; при закрытии (фон, минута простоя) — несохранённое уходит в
  очередь диска, ключи обнуляются в её конце.
- Фон: `onBackground` сам закрывает приложение; внутри своих выборщиков файла, «Сохранить как»,
  «Поделиться», камеры и ключа телефона — нет (`SecretHold.outside`). Шторка secret-return до него не
  доходит: закрытое приложение нечем накрывать. Superizer не менялся.
- Копирование: `LocalClipboard`, который ничего не принимает; `TextToolbar` и новое контекстное меню
  без «Копировать»/«Вырезать» (и без «Поделиться», «Перевести»); Ctrl/⌘+C/X проглатываются.
- Экспорт — armored-текст (`age -a` / `openssl -a`), имя `cr-note-<дата>.age|.enc`; «Сохранить файл»
  и «Поделиться». На ключи: ключи телефона, сохранённые ключи, вставленные `age1…`/SSH, ключи GitHub.
  Пароль — дважды, ≥ 12, «Сгенерировать» заполняет оба поля и показывает.
- Импорт: файл или QR (один код с armored-текстом или UQR1-серия). age паролем, age ключом телефона
  (`SshKeyring.decrypt`), openssl паролем. Совпадающие по тексту и `created` пропускаются.

Не проверено / открыто:
- На телефонах не запускалось: ни Android-Keystore RSA с `CryptoObject`, ни Secure Enclave с
  `BiometryCurrentSet` (iOS-код только скомпилирован). Нужны руками: первый вход, вход, `178500`,
  смена отпечатков/лица, телефон без биометрии, фон посреди записки, экспорт → `age -d` на компьютере.
- Тест D662 на эмуляторе («Keystore отказывает без `CryptoObject`») не написан: здесь нет эмулятора
  с отпечатком.
- **Q287. Простой при наборе текста** — закрыт, ответ владельца: не чинить. Хост считает активностью
  только касания; кто печатает минуту, не касаясь экрана, будет закрыт, записанное сохранится.

### D669. QR в конец записки (владелец, 0.5)

> «Надо добавить прям там внутри чтение QR незашифрованного: нажать на кнопку, откроется камера, и то,
> что отсканировалось, добавится в конец записки.»

- В записке сверху кнопка «QR» (только если у хоста есть камера). Камера → текст кода как есть, без
  расшифровки и разбора, — в конец записки: в пустую — сам код, иначе с новой строки. Курсор — после
  вставленного. Сохраняется как набранный текст (через 0,5 с, шифром директории).
- Ничего не прочитано (камеру закрыли) — ничего не добавлено.
- Камера уходит на свой экран через `SecretHold.outside`: этот уход в фон приложение не закрывает.
- Тест: `CrNoteTest.aScannedQrCodeGoesToTheEndOfTheNoteAsItIs`.
