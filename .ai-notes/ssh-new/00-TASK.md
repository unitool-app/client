## 1. Цель одним абзацем

Unitool получает: SSH-ключи, которые живут в чипе, где чип есть, и под паролем ключа, где чипа
нет; хранилище секретов для всех приложений, запечатанное хостом; полный бэкап данных
приложений на ключи GitHub; диагностику с честными надписями о том, как и где всё хранится, и
самопроверку, которая выполняет криптографию на самом устройстве и пишет отчёт. Superizer
получает только контракты и механику (контракт 3), все реализации — в Unitool.

## 3. Порядок работы

1. **Б1 первым.** В обоих репозиториях лежит незакоммиченный Superizer 0.3.0 (замок + iOS) и
   Unitool с 2FA-замком и iOS. Сначала: `verify.sh` в superizer → коммит → публикация 0.3.0 →
   `verify.sh` в unitool с `SUPERIZER_FROM_MAVEN=1` → коммит. Не смешивать это с новой работой.
2. **Шаг 0** (07 §4, 04 §2): `SelfTest` как инструментальный тест на `unitool35` и телефоне
   владельца, P1–P9; P10–P14 — на iPhone через `ios.yml` `device` + подпись владельца (06 §4.1).
   Результаты вписать в таблицу 04 §2 **до** шага 5. Правило по Ed25519 — 04 §2.
3. **Шаг 1**: Superizer 0.4.0, только контракт 3, механика, UI-слоты, фейки (07 §2.1, §2.4).
   Один коммит на контракт, один на публикацию. После него библиотеку не трогать.
4. **Шаги 2–7** только в Unitool (07 §4). Библиотека через `includeBuild`, публикация не нужна.
5. Каждый шаг: красный тест → код → зелёный `./scripts/verify.sh` в затронутом репозитории →
   коммит. Инварианты 03 §1 — часть definition of done, не «потом».

## 4. Как работать: правила

- **Заметки — спецификация.** Отклонение от заметки — это сначала правка заметки с пометкой
  «(impl)» и причиной, потом код. Решение, которое требует владельца, — новый вопрос в
  README с номером (следующий — 90) и стоп.
- **Ни одной надписи о защите от руки** (D179). Только коды каталога 06 §6.1; текст — в
  `composeApp/…/i18n/DiagnosticsStrings.en.kt`, перевод — `.ru.kt`; компилятор проверяет
  полноту. То же для листинга и `play/PRIVACY.md`.
- **Секреты.** `String` для закрытого материала запрещён (D155); `SecretBytes` и `CharArray`,
  обнуление в `finally`. Канарейки в тестах маскированы (D157). Логи, события, снапшоты,
  исключения, отчёт диагностики — без секретов (I5, I20).
- **Модуль `services/ssh` не зависит от сети** (I-сеть): `verify.sh` это проверяет.
- **Ключ без пароля не принимается, короче 12 — перешифровать** (D167). Бэкап — данные, не
  ключи (D170). Сейф на ssh-ключе кэширует секреты, не ключ (D176).
- **Superizer:** `explicitApi()`, BCV-дампы обновлять осознанно, CHANGELOG в том же коммите.
  Ничего платформенного, ни строки текста для человека, ни криптопримитива (D183).
- **Коммиты:** английские, одна мысль, заголовок — что изменилось и почему, как в `git log`.
  Не коммитить и не пушить без явной просьбы владельца; на `main` не работать напрямую, если
  владелец не сказал иначе.
- **Тесты с настоящими утилитами** (`ssh-keygen`, `ssh-add`, `age`): пропуск по имени, если
  утилиты нет; в CI ставятся (03 D158).
- **iOS без Mac**: проверять по отчёту самопроверки с iPhone (D180). Пока отчёта нет, писать в
  заметках и CHANGELOG «написано, не выполнялось».
- **Память сессии**: ключевые решения уже в `superizer-ssh-keyring-plan.md`; при новых
  решениях владельца — обновлять её, не заводить дубликаты.
