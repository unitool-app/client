# Секретные приложения: возврат только через замок

> Версия 0.2, 2026-10-27. Решения D620–D623. Следующие номера — D624 / Q265.
> Построено в Superizer 0.7.1 (не закоммичено), поверх 0.7.0 cr-restore (`LockPolicy.WhileHolding`,
> D598). Что вышло — §«Сделано».

## Что просил владелец

«Все приложения, которые секретные, должны при открытии быть с заглушкой: если они ждущие — будет
замок, если нет — редирект на главную». «Ждущее» — секретное приложение, которое осталось открытым,
когда человек ушёл из Unitool, и ждёт его при возврате. Уточнения:
- замок — при **любом** возврате, не только после 5 минут;
- обычных приложений это не касается: ни редиректа, ни замка;
- на устройстве без блокировки экрана — просто главная.

## Как сейчас (Superizer 0.6.1)

- `closeSecretAfterLongBackground`: секретное приложение закрывается при возврате, только если было
  в фоне `secretBackgroundLimit` (5 мин) и дольше. Короткий выход — экран как был, без замка.
- Миниатюра в недавних уже скрыта (`RecentsPreview(hidden = true)`, D253).
- Простой в минуту закрывает (0.6.1). Это остаётся.

## Решения

- **D620. Любой возврат к открытому секретному приложению — под шторку.** Уход в фон с открытым
  секретным приложением закрывает замок для него (как `close("left a held secret")` у
  `WhileHolding`), без grace. При возврате вместо экрана шторка; пускает только `UserPresence`
  (Face ID / Touch ID / отпечаток / код устройства). Приложение живо под шторкой, состояние не
  теряется.
  - Исключения: `SecretHold.outside` (свой выбор файла, «Сохранить как») и шторка, открытая самой
    системой авторизации (`prompting`).
  - Простой (минута) по-прежнему закрывает секретное приложение, а не опускает шторку — если
    оно само ничего не держит через `SecretHold`.
- **D621. Нет блокировки экрана — главная.** `availability != Available`: при возврате приложение
  закрывается (`handler.close(force = true)`) и `ShellCommand.Close`, без баннера D140.
- **D622. Приложения уже нет — главная.** Процесс умер или шелл восстановил маршрут секретного
  приложения, а сессии нет (снимков у секретных нет, idea/09): шелл уходит на главную, а не рисует
  пустой экран.
- **D623. Предел 5 минут для секретных уходит.** `secretBackgroundLimit` больше не нужен: при любом
  возврате решает D620/D621. `SuperizerBuilder.secretBackgroundLimit` остаётся как устаревший
  (no-op) до следующего мажорного контракта. Обычные приложения — без изменений.

## Где

- `host/lock/AppLock.kt`: секретное открытое приложение считается в `guarded` (как `holding`), и
  `onBackground` закрывает для него замок без grace, кроме `away`.
- `SuperizerHost.kt`: `closeSecretAfterLongBackground` → `closeSecretWithoutLock` (только D621);
  отмена на шторке для секретного — закрыть и на главную.
- Шелл (`ui/shell`): маршрут секретного приложения без сессии → главная (D622).
- Тесты: `SecretAppsTest` (возврат через 1 с — шторка; без блокировки — главная; `outside` —
  без шторки), `LockShellTest` (отмена на шторке → главная).
- Unitool: поднять версию Superizer; `ssh-keys` (host screen) — проверить, что его тоже покрывает.

## Сделано (Superizer 0.7.1, 2026-10-27)

- `AppLockController.holdSecret(id)` (internal): открытое секретное приложение входит в
  `LockState.holding` от запуска до закрытия, при любой политике. `holding(false)` от самого
  приложения его оттуда не убирает. `guarded` = политика ∪ `holding`. На входе `present` (шторки нет),
  если политика сама не охраняет приложение — `Required` по-прежнему спрашивает на входе.
- `SuperizerHost`: `watchHeldSecrets` зовёт `holdSecret` при открытии секретного приложения;
  `closeSecretAfterLongBackground` удалён; `secretBackgroundLimit` — `@Deprecated`, ничего не делает.
  Без блокировки на устройстве уход закрывает приложение и шлёт `ShellCommand.Close` (код
  cr-restore, теперь и для секретных).
- D622 уже было так: `destination` в шелле — `remember`, не `rememberSaveable`, а снимков у
  секретных нет, поэтому после смерти процесса шелл стартует с главной.
- Тесты: `SecretAppsTest` — возврат через секунду и через три часа под шторкой, без блокировки —
  главная, `outside` — без шторки, закрытое ничего не держит. `./gradlew verify` в Superizer — зелёный.
- Не покрыто: экран хоста `ssh-keys` (не приложение, замок его не видит) — как и с простоем в 0.6.1.
- Последствие для cr-restore: раз приложение секретное, шторка при возврате теперь всегда, даже
  когда ничего не расшифровано.
