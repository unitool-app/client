# 09 — Открытые вопросы

Решения ниже приняты по умолчанию так, как указано; если владелец хочет иначе — менять до шага
3 плана дёшево, после шага 7 — уже нет.

1. **Имя и координаты.** `cx.m42.superizer` / group `cx.m42.superizer`. Каталог `.ai-notes/superizer`
   задаёт имя; если библиотека пойдёт наружу (как Adminizer на GitHub), нужен org и домен для
   group. По умолчанию — `cx.m42`.
2. **Где жить библиотеке прямо сейчас** — в этом репо (`superizer/`, D9) или сразу отдельным
   репо + `includeBuild`. По умолчанию — здесь: один PR, одна сборка, один CI; выделение — механика.
3. **`core` без `compose.ui`** (только `compose.runtime`) — стоит ли усилий? Плюс: контракт не
   привязан к рендеру, `AppIcon` вместо композабла. Минус: чуть больше типов. По умолчанию — да,
   это дёшево сейчас и дорого потом.
4. **Один активный экземпляр (D4)** — достаточно для MVP? Стек приложений (Calculator открыл
   Converter, back возвращает в Calculator с состоянием) — следующий шаг, контракт совместим.
   По умолчанию — один, а `openApp` из приложения закрывает текущее.
5. **Камера для QR** — какой шаг после MVP и только Android? По умолчанию — после MVP, только
   Android (CameraX + ML Kit), desktop/web остаются с текстовым вводом.
6. **Промокоды удалённо** — есть ли уже сервер/формат (Adminizer-модуль?). По умолчанию —
   локальная таблица, интерфейс `PromoCodeResolver` под замену.
7. **Push (FCM)** — нужен ли в Unitool вообще, или интерфейс + no-op до появления сервера.
   По умолчанию — no-op; реализация по образцу `agentiz/push` когда появится backend.
8. **Auth** — какой провайдер (Adminizer-сессия, как в agentiz?). По умолчанию — анонимный.
9. **Источник курсов** — frankfurter.app (ЕЦБ, без ключа, CORS). Если нужен RUB актуальный —
   у ЕЦБ его нет с 2022; тогда open.er-api.com. По умолчанию — frankfurter + URL в конфиге.
10. **Scientific-режим калькулятора** — три унарные операции достаточно как «видимый эффект
    конфига»? По умолчанию — да.
11. **Standalone-sample** (`samples/standalone-calculator`) — делать в MVP или сразу после?
    По умолчанию — сразу после шага 12, это лучшее доказательство §16–18.
12. **Язык документации библиотеки** — README `superizer/` на английском (как README Unitool и
    docs Adminizer), заметки здесь — на русском. По умолчанию — так.

Добавлено в ревизии 1 (11):

13. **`contractVersion` — целое или semver?** По умолчанию — целое, отдельно от версии
    библиотеки: приложению нужно одно сравнение «хост не старше N», а не диапазоны.
14. **Восстанавливать сессию при каждом старте или только после смерти процесса?** Отличить
    одно от другого нельзя надёжно на всех трёх платформах. По умолчанию — при каждом старте,
    если снимку меньше суток; deep link при старте имеет приоритет. Если владелец хочет «всегда
    Home» — это один флаг в `Superizer.build`.
15. **Какие `ServiceKey` объявить в MVP?** По умолчанию — ни одного: `service(key)` и `requires`
    есть, реестр хоста пуст. Первый кандидат — камера для QR (вопрос 5), она и проверит механизм.
16. **`fallbackToDefault` по умолчанию true или false?** По умолчанию — true: калькулятор с
    битым QR полезнее экрана ошибки. Test App ставит false, чтобы показать второй путь.
17. **Нужен ли `AppRuntime` уровня приложения в MVP**, если push и фоновые задачи — заглушки?
    По умолчанию — да, потому что это форма `setup(ctx)` и `HostRuntimeFactory`, и менять её после
    шага 4 значит переписывать все реализации runtime и подделки.

Добавлено в ревизии 2 (13):

18. **Firebase-проект и сервер отправки** — есть ли, кто владеет? До ответа — шаг 15 не начинается,
    но всё до транспорта делается и тестируется на фейке.
19. **Кто локализует текст уведомления** — сервер (по `lang` из регистрации устройства, по
    умолчанию) или хост по `topic`? Второе потребует таблиц строк для тем в приложении и
    расширения контракта; не делаем без причины.
20. **Домен для App Links** (`https://…/app/…` вместо `unitool://`) — нужен ли и какой? По умолчанию —
    только своя схема; App Links добавляются `intent-filter`-ом и `assetlinks.json` без изменений в коде.
21. **Web Push в wasm** — нужен ли вообще? По умолчанию — нет; `PushTransport.wasmJs` остаётся no-op.
