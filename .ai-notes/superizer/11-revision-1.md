# 11 — Ревизия 1: зрелость контракта до начала кода

Дата: 2026-09-20. Повод: вопросы «как шарить как фреймворк», «свой UI / наборы компонентов»,
«что подправить, чтобы стало зрелее». Все изменения внесены в 01–06, 08, 09; здесь — сводка
с мотивацией, чтобы при ревью было видно, что и зачем поменялось, не сравнивая файлы.

Принцип отбора: правится только то, что дёшево до шага 3 плана и дорого после шага 7, то есть
форма публичных типов `core`. Реализации, экраны и приложения не трогались.

## Что изменено

| # | Решение | Было | Стало | Зачем |
|---|---|---|---|---|
| D14 | Версия контракта | нет; версия только у моста в 10 | `HostInfo.contractVersion`, `SuperizerApp.minHostContract`, `RegistrationRejected`; explicit API + BCV для `superizer:*` | Библиотека шарится между хостами как npm-пакет. Без версии и API-дампов каждый рефакторинг молча ломает чужой хост |
| D15 | Два уровня runtime | один `AppRuntime` на launch; listener из `setup` получал «app-scoped runtime» неясного происхождения | `AppRuntime` (enable → disable) и `InstanceRuntime : AppRuntime` (launch → dispose) с `navigation` и своим scope | Push для закрытого приложения, deep links, фоновые задачи должны на чём-то работать. Это enable/request из Adminizer |
| D16 | Снимок состояния | `onClose` сам писал в storage; про смерть процесса ни слова | `saveState()`/`restore()`, `SessionSnapshot`, `restoreLastSession()` | Android убивает процесс в фоне независимо от D4. Тот же механизм даст стек приложений позже |
| D17 | Lifecycle хоста | нет | `runtime.lifecycle: StateFlow<HostLifecycle>`, `onBackground`/`onForeground` | Конвертер не должен опрашивать сеть в фоне; снимок пишется именно в `Background` |
| D18 | Ошибки конфига | `decode` молча возвращал default | `Result<C>`, событие `ConfigRejected`, `fallbackToDefault`, `schemaVersion` + `migrate` | QR с «scientific» открывал обычный калькулятор без объяснений. Миграции — чтобы через год знать, что лежит в storage |
| D19 | Реестр сервисов | 12 полей в интерфейсе; новый сервис ломает все реализации | ядро полями + `service(ServiceKey<T>)`, `metadata.requires`, `HostInfo.services` | Расширяемость без поднятия `contractVersion`; `requires` = `permissions` манифеста из 10 бесплатно |
| D20 | Команды хоста | промокод `SERVICE` → `Activation(AppId("service-menu"))`, shell знал магическое имя | `ActivationResult.HostCommand(OpenServiceMenu)` | Одно зарезервированное имя всегда размножается |
| D21 | Проверки сборкой | правила зависимостей «ревью, позже задача» | `checkDependencyRules` с шага 1; `AppContractTest` в `testing` | Нарушение графа через полгода не вычистить; TCK даёт каждому приложению базовые гарантии бесплатно |
| D22 | Результат `openApp` | `Boolean` | `Result<AppResult>` с типизированными `NavigationError`; `payload` пока всегда null | Резерв под «открыть X и получить значение» без смены сигнатуры |
| D23 | Токены темы | в `ui` вместе с компонентами | отдельный `superizer:ui-theme` | Сторонние наборы компонентов зависят от токенов, не от всего `ui` |

## Что сознательно не менялось

- **D4, один активный экземпляр.** Стек — следующий шаг; D16 делает его дешёвым, но не тянет в MVP.
- **Обмен данными между приложениями.** Только сигнатура (D22). Протокол «результата» проектируется
  вместе со стеком.
- **UI только Compose.** `Content()` остаётся `@Composable`. Нативные экраны (UIKit, Android View)
  возможны через interop внутри `Content()`, рамка хоста при этом не заменяется. Полностью
  не-Compose приложения — Tier 2/3 из 10. Записано как ограничение, не как задача.
- **Изоляция в одном процессе.** Storage-префикс и запрет `openApp` на скрытые — достаточно для
  Tier 0. Настоящие границы прав — у моста (10).

## Что это стоит

Оценка сверх исходного плана: `ServiceKey`/`requires`/BCV/`checkDependencyRules` — день на шаге
1–3; два уровня runtime и lifecycle — день на шаге 4; снимки и `restoreLastSession` с тестами —
день на шаге 5; `AppContractTest` — полдня. Итого ~3.5 дня, все в первых шести шагах плана.

## Как проверить, что ревизия «взялась»

- `apiDump` для `core` существует и `apiCheck` зелёный после шага 3.
- `ProbeApp` в `ExtensibilityTest` (05) объявляет `minHostContract = 99` в отдельном тесте и
  **не** появляется на All Apps, а в Service Menu видна причина.
- Тест handler-а: убить и поднять handler на том же storage — калькулятор открывается с тем же `entry`.
- Test App с промокодом, где `config` — не JSON: лента показывает `ConfigRejected`, экран показывает
  default-конфиг (или экран ошибки, если Test App ставит `fallbackToDefault = false`).
