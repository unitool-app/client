## Коротко

1. **`cr-restore`** — скрытое приложение. Открывается только точным промокодом `[cr-restore]`, на
   один визит. Его нет ни в каталоге, ни на Home.
2. **Первый экран — выбор способа:** age, openssl, split-qr.
3. **Вход:** QR (несколько подряд, если длинное), файл или вставка.
4. **Выход:**
   - текст — на экран, «Копировать» и «Сохранить файлом»;
   - двоичное — «Сохранить файл».
5. **Ничего не сохраняется**: ни расшифрованное, ни ключи, ни пароли, ни настройки. Только
   память, и при закрытии всё стирается.
6. **Замок:** на вход не нужен. Пока внутри есть расшифрованное, вернуться в приложение (после
   простоя, из фона, по промокоду ещё раз) можно только через замок устройства.
7. **Скриншоты и запись экрана запрещены.**
8. **age и openssl — всё, что умеют сами утилиты**, кроме того, что на телефоне невозможно (D614,
   D617). Каждый вариант проверяется против настоящих `age` и `openssl` (D618).

## Решения

### Приложение

- **D595. Имя и вид** (пересмотрено в 0.4).
  - `apps/cr-restore`, AppId `cr-restore`, пакет `cx.m42.apps.crrestore`, `CrRestoreApp`.
  - Заголовок на экране — `cr-restore` в обоих языках (ответ на 262).
  - В манифесте:
    - `secret = true`;
    - `hidden = true`;
    - `protection = AppProtection(lock = LockPolicy.WhileHolding, secureWindow = true)`;
    - `minHostContract` — новый (D598).
  - Работает офлайн. Тексты на русском и английском.
- **D596. Промокод `[cr-restore]` — точный**, как `[ssh-keys]`.
  - Работают `[cr-restore]` и `{cr-restore}`. `cr-restore`, `CR-RESTORE` и `[cr restore]` не
    открывают ничего.
  - В коде только хеши `scripts/promo-hash.sh`. Строка — `ActivationResult.Success(Activation(AppId("cr-restore")))`.
  - Сам код записывается в `.secrets/promo-codes.md`.
  - Код короткий, хотя idea/09 советует скрытым приложениям 12+ случайных знаков. Владелец
    оставил так (ответ на 263): без чужого файла и ключа приложение бесполезно.
- **D597. Ничего не сохраняется** — ни расшифрованное, ни второй раз ничего:
  - вход, пароли, ключи, части, результат и настройки — только в памяти экземпляра;
  - приложение не пишет в `runtime.storage`, `saveState()` → null;
  - конфиг пустой, в бэкапе ничего нет; хост не пишет вход и выход в журнал событий
    (`sensitive`, D134);
  - каждое открытие начинается с умолчаний;
  - при закрытии (кнопкой, по простою, после замка, при смене приложения) всё обнуляется:
    `ByteArray.fill(0)`, `SecretBytes.wipe`, поля паролей очищаются;
  - «Копировать» кладёт в буфер с пометкой «чувствительное» и убирает через минуту, как
    `CodeClipboard` в 2FA. Буфер — единственное место, куда расшифрованное уходит из приложения
    без «Сохранить».
- **D598. Замок — только пока приложение держит расшифрованное** (ответ на 256, пересмотрено в 0.4).
  - **На вход замка нет.**
  - Приложение говорит хосту `runtime.lock.holding(true)`, как только расшифровало, и
    `holding(false)` после «Начать заново» и стирания.
  - Пока `holding == true`:
    - по простою (1 мин) приложение **не закрывается**, а закрывается шторкой замка;
    - при уходе в фон шторка тоже опускается, без отсрочки `grace`;
    - повторного входа по промокоду в живой экземпляр не бывает: чтобы ввести код, из приложения
      надо выйти, а выход его закрывает и стирает (вышло иначе, чем в 0.4);
    - снять шторку — замок устройства (биометрия или код телефона);
    - «Закрыть» на шторке закрывает приложение и всё стирает.
  - Пока `holding == false` — как сейчас у скрытых приложений: по простою закрывается, замка нет.
  - Убит процесс — данные пропадают вместе с ним, замок не нужен.
  - Если на телефоне нет блокировки экрана, при простое или уходе в фон приложение закрывается и
    стирается. Шторку без замка поставить нельзя.
  - Нужна правка Superizer:
    - `LockPolicy.WhileHolding` и `AppLockPort`/runtime `holding(Boolean)`;
    - `closeWhenIdle` при `holding` вызывает `lockNow()` вместо `close`;
    - тесты в `LockShellTest`;
    - новый номер контракта, публикация Superizer.
- **D599. Первый экран — выбор способа.** Три строки с пояснением:
  - **age** — «файл age: ключом этого телефона, своим ключом или паролем»;
  - **openssl** — «`openssl enc`: пароль или ключ»;
  - **split-qr** — «секрет, разделённый на части-QR».

  Если отсканирован явно чужой формат — «Похоже на age — открыть там?» (D601).

### Вход и выход — общие

- **D600. Вход.**
  - «Сканировать» (если есть `QrScanner`), «Открыть файл» (если есть `FilePicker`), «Вставить».
  - Несколько QR подряд: длинное печатается `unitool qr encode --split`. «Сканировать ещё»
    дописывает кусок с новой строки, на экране «3 QR, 2 140 знаков».
    - Для армора (age, ucrypt) конец виден по `-----END …`, и тогда расшифровка начинается сама.
    - Для openssl нужна кнопка «Расшифровать».
  - В QR — только текст: сканер отдаёт строку. Двоичное — через «Открыть файл».
- **D601. Узнавание формата** (только подсказка, способ выбирает человек):
  - age — `age-encryption.org/v1` или `-----BEGIN AGE ENCRYPTED FILE-----`;
  - openssl — `Salted__` или base64 с `U2FsdGVkX1`;
  - split-qr — `-----BEGIN UCRYPT FILE-----`, магия `\x89UCR` или ссылка-часть.

  Файл openssl без соли (`-nosalt`, `-K`) ничем не помечен, его не узнать.
- **D602. Выход** (пересмотрено в 0.4).
  - **Текст** — корректный UTF-8 без управляющих символов, кроме `\n`, `\r`, `\t`, и не больше
    64 КБ (ответ на 258). На экране — моноширинный выделяемый текст. Кнопки: «Копировать» и
    «Сохранить файлом» (ответ на 259, имя `…​.txt`).
  - **Иначе — файл:** размер, имя и «Сохранить файл». Имя:
    - split-qr — из метаданных `ucrypt`;
    - иначе — имя открытого файла без `.age`/`.enc`/`.ucrypt`;
    - иначе — `cr-restore-<дата>.bin`.
  - «Начать заново» — стирает и возвращает к выбору способа. `holding(false)`.
- **D603. Сохранение — новый сервис `services/file-saver`.** `FileSaver.save(name, bytes, mime): Boolean`.
  - Android — `ACTION_CREATE_DOCUMENT`.
  - iOS — `UIDocumentPickerViewController(forExporting:)` из временного файла в `tmp`, который
    удаляется сразу после ответа.
  - Desktop — диалог файла.
  - Сервис необязательный (D19), байты после записи обнуляются.
  - Пока открыт системный диалог сохранения или выбора файла, шторка не опускается: это не уход
    из приложения.

### age — всё, что умеет `age` (ответ на 257)

- **D604. Чем открывать** (пересмотрено в 0.4). Экран age показывает получателей файла (D605)
  и предлагает то, что к ним подходит:

  | Получатель в файле | Чем открыть | Откуда |
  |---|---|---|
  | `ssh-ed25519`, `ssh-rsa` | ключ этого телефона | `SshKeyring.decrypt` — хост сам находит ключ, спрашивает разрешение и замок ключа; приложению ключ не виден |
  | то же | закрытый SSH-ключ из файла | «Открыть файл» / «Вставить»: OpenSSH (`-----BEGIN OPENSSH PRIVATE KEY-----`, с паролем — bcrypt, в kit есть) и PEM RSA (`BEGIN RSA PRIVATE KEY`, без пароля). Ключ в чужом приложении живёт только в памяти, потом обнуляется |
  | `X25519` (`age1…`) | `AGE-SECRET-KEY-1…` | вставить, отсканировать QR или открыть файл ключей (`age-keygen -o`, комментарии `#` пропускаются, ключей может быть несколько) |
  | `scrypt` (`age -p`) | пароль | поле пароля |
  | постквантовый гибрид ML-KEM-768 + X25519 (D614) | его закрытый ключ | как `AGE-SECRET-KEY` |
  | файл ключей, сам зашифрованный паролем (`age -d -i keys.age`) | пароль, потом ключи из него | «Открыть файл» в поле ключа узнаёт age-файл и спрашивает пароль |
  | плагин (`age-plugin-yubikey`, `-tpm`, `-se` …) | **нельзя** | плагин — отдельная программа на компьютере; приложение показывает «Нужен плагин `age-plugin-…`, на телефоне он не работает» |

  Настроек у age нет: всё нужное — в заголовке файла.
- **D605. Что видно до расшифровки** — заголовок без ключа (`Age.stanzas`):
  - «Зашифровано для: ssh-ed25519 · метка `AbCd12` (ключ «Телефон»); X25519; пароль (scrypt,
    сложность 2¹⁸)».
  - Сложность scrypt больше 2²² → предупреждение «расшифровка займёт долго и много памяти». Выше
    предела `age` (`work factor` > 22 у него по умолчанию отказ) — тот же отказ, как у `age`.
  - Ответы `SshOutcome`:

    | Ответ | Сообщение |
    |---|---|
    | `NoKey` | «Не для ключей этого телефона» |
    | `Unusable` | «Ключ недоступен» |
    | `Refused` | «Отменено» |
    | `Busy` | «Ключ занят» |
- **D606. По правилам age.** Файл с `scrypt` не может содержать других получателей: `age`
  отказывает, и мы тоже. Неверный ключ или пароль → «Не подошло». Порча файла → «Файл повреждён»
  (payload под ChaCha20-Poly1305 проверяется по кускам 64 КБ). Результат отдаётся только
  целиком проверенным.

### openssl — всё, что умеет `openssl enc` (ответ на 257)

- **D607. Формат** (пересмотрено в 0.4). Два вида:
  - **с солью** (по умолчанию): `Salted__ ‖ соль 8 ‖ шифротекст`;
  - **без соли** (`-nosalt`) или **с готовым ключом** (`-K hex -iv hex`): только шифротекст.

  Каждый вид — двоичный или `-a` (base64 с переносами или `-A` одной строкой).
- **D608. Параметры на экране** (пересмотрено в 0.4). Каждый раз умолчания (D597).

  | Поле | По умолчанию | Варианты |
  |---|---|---|
  | **Пароль** (скрыт, «показать») | — | или переключатель «Ключ и IV в hex» (`-K`, `-iv`) |
  | **Итерации** | 10000 | любое; при «старом» способе поле скрыто |
  | **Ещё ▸ Шифр** | `aes-256-cbc` | все шифры `openssl enc -list` (D609) |
  | **Ещё ▸ Ключ из пароля** | PBKDF2 (`-pbkdf2`) | «старый» (`EVP_BytesToKey`, без `-pbkdf2`) |
  | **Ещё ▸ Дайджест** (`-md`) | `sha256` | все из D609, кроме MD5 (ответ на 261) |
  | **Ещё ▸ Соль** | «в файле» | «нет» (`-nosalt`) |
  | **Ещё ▸ Без паддинга** (`-nopad`) | выкл. | вкл. |

  Под полями — команда, которая подходит под выбранное, например:
  ```
  openssl enc -aes-256-cbc -pbkdf2 -iter 600000 -a -in FILE | unitool qr encode --split
  ```
- **D609. Что поддерживаем** — по `openssl enc -list` OpenSSL 3.x (здесь 3.0.13; на CI — свежий
  3.x, список сверяется тестом, D618):

  | Группа | Шифры | Режимы |
  |---|---|---|
  | AES-128/192/256 | `aes` | `cbc`, `ecb`, `cfb`, `cfb1`, `cfb8`, `ofb`, `ctr` |
  | ARIA-128/192/256 | `aria` | те же |
  | Camellia-128/192/256 | `camellia` | те же |
  | SM4 | `sm4` | `cbc`, `ecb`, `cfb`, `ofb`, `ctr` |
  | ChaCha20 | `chacha20` (без Poly1305 — `enc` его не умеет) | поток |
  | 3DES | `des-ede3`, `des-ede` | `cbc`, `ecb`, `cfb`, `cfb1`, `cfb8`, `ofb` |
  | провайдер `legacy` | `des`, `desx`, `bf`, `cast5`, `rc2` (40/64/128), `rc4` (40/128), `seed`, `idea` | их режимы |

  - **Дайджесты для `-md`:** `sha1`, `sha224`, `sha256`, `sha384`, `sha512`, `sha512-224`,
    `sha512-256`, `sha3-224/256/384/512`, `sm3`, `blake2b512`, `blake2s256`, `ripemd160`; из
    `legacy` — `md4`, `whirlpool`, `mdc2`. **Без MD5** (ответ на 261).
  - **Не бывает в `openssl enc`:** AEAD-режимы (GCM, CCM, OCB, Poly1305) — `enc` их не
    принимает; `-engine`, `-z` (zlib, только в особых сборках).
- **D610. Код — свой, в kit, без системного OpenSSL** (обсуждение 2026-10-27):
  - `kit.crypto`:
    - блочные шифры и режимы;
    - `pbkdf2(hash, …)`;
    - `evpBytesToKey(hash, …)`;
    - дайджесты из D609.

    Всё константного времени, где это возможно. Таблицы S-box у DES, Blowfish, CAST, SEED — с
    оговоркой в коде: это расшифровка своего файла, не сервер.
  - `kit.openssl.OpensslEnc` — `decrypt(input, params)` и `encrypt` (для тестов и будущего CLI).
  - Ошибки:
    - плохой паддинг → «Неверный пароль, итерации, шифр или дайджест»;
    - режимы без паддинга (`ctr`, `ofb`, `cfb`, потоковые, `-nopad`) ошибку не видят никогда;
      там всегда выход и предупреждение «`openssl enc` не проверяет целостность: если результат
      не тот, неверны пароль или параметры».

### split-qr

- **D611. Сборка — как в 0.1.**
  - Контейнер и части в любом порядке.
  - Экран: «Контейнер ✓ (нужно 2 из 3) · Части 1 из 2».
  - Повтор части или часть чужого набора — сообщение.
  - Когда частей хватает, расшифровка начинается сама.
  - `disagreeing` → результат и предупреждение.
  - MAC не сошёлся → «Части не подходят».
  - `Inspected.Newer` → «Новее этого Unitool».

  Разделения на телефоне нет (253). Части в vault нет (255).

### Новые в 0.4

- **D613. Запрет скриншотов** (ответ на 260) — `AppProtection(secureWindow = true)`, уже в
  Superizer:
  - Android — `FLAG_SECURE` на всё приложение: скриншот, запись, трансляция, миниатюра в
    недавних;
  - iOS запретить скриншот не даёт. Там при записи и трансляции экрана (`UIScreen.isCaptured`) и в
    переключателе приложений вместо экрана заглушка — так уже делает Superizer
    (`ui/src/iosMain/…/SecureWindow.ios.kt`). Поэтому ещё и D619.
- **D614. Постквантовый получатель age.** В age 1.3 (2025) появились гибридные ключи ML-KEM-768 +
  X25519. Делаем, если они есть в той версии `age`, что стоит на CI. Тест D618 проверяет это сам:
  если `age-keygen` умеет `-pq`, то и мы.
  - Нужно в kit: ML-KEM-768 (FIPS 203) с векторами NIST.
  - Это самая большая криптография в заметке.
- **D615. scrypt для age** — свой, в kit (Salsa20/8, BlockMix, ROMix поверх PBKDF2-SHA256), с
  векторами RFC 7914 §12. Память при `N = 2¹⁸` — 256 МБ. На телефоне это проверяется заранее:
  - если сложность больше, чем выдержит устройство, — отказ до начала, а не падение;
  - предел — по свободной памяти, не меньше умолчания `age` (2¹⁸).
- **D616. Долгие операции** (scrypt, PBKDF2 на миллионы итераций, RSA) — в фоне, с
  «Расшифровываю…» и «Отменить». Простоя при этом не бывает: шторка не опускается, пока идёт
  работа.
- **D617. Невозможно на телефоне — и так и написано на экране:**
  - плагины age;
  - `openssl -engine` и аппаратные ключи;
  - файлы `openssl enc`, сделанные с `-md md5` или старым `openssl` 1.0 (ответ на 261).
- **D618. Проверка на настоящих бинарях** (ответ на 257) — главное против расхождений.
  1. **Векторы стандартов** в `commonTest` для каждого примитива:
     - AES — FIPS-197;
     - режимы — SP 800-38A;
     - ARIA — RFC 5794;
     - Camellia — RFC 3713;
     - SM4 — GB/T 32907;
     - ChaCha20 — RFC 8439;
     - DES/3DES — SP 800-67;
     - Blowfish, CAST5 (RFC 2144), RC2 (RFC 2268), RC4, SEED (RFC 4269), IDEA;
     - SHA-2 / SHA-3 — FIPS 180-4 / 202;
     - SM3, BLAKE2 (RFC 7693), RIPEMD-160, MD4, Whirlpool, MDC-2;
     - PBKDF2 и scrypt — RFC 7914;
     - ML-KEM — FIPS 203 / ACVP.
  2. **Матрица против настоящих утилит** — `desktopTest`, на CI обязательно, локально — если
     бинари есть. Скрипт `scripts/cr-restore-matrix.sh` берёт список из самих утилит
     (`openssl enc -list`, `openssl list -digest-commands`, `age --help`).
     - **openssl:** каждый шифр × режим × {PBKDF2 с `-iter` 1/1000/600000, старый KDF} × каждый
       дайджест × {соль, `-nosalt`, `-K/-iv`} × {двоичный, `-a`, `-a -A`} × {паддинг, `-nopad`}.
       Данные — 0/1/15/16/17/4096/70000 байт, кириллица в пароле и данных. `openssl` шифрует → мы
       расшифровываем; мы шифруем → `openssl enc -d`.
     - **age:** каждый вид получателя (`ssh-ed25519`, `ssh-rsa` 2048/4096, X25519, scrypt,
       `-pq`), несколько получателей сразу, `-a` и двоичный. Ключи — из `age-keygen` и
       `ssh-keygen`, в том числе OpenSSH-ключ с паролем. Данные — 0 байт, ровно 64 КБ, 64 КБ ± 1,
       200 КБ. В обе стороны, где у нас есть шифрование.
     - **Порча:** каждый байт заголовка, обрезка, перестановка кусков → отказ (age) или
       предупреждение (openssl).
  3. **Замороженные файлы** — по одному на каждую клетку матрицы, сделанные утилитами, лежат в
     `commonTest/resources` и прогоняются **на всех целях**: Android, iOS-симулятор, linuxX64.
     Так видно, что расшифровка одинакова везде, а не только на JVM.
  4. **CI:** `apt-get install age openssl`. Если в репозитории Ubuntu `age` старше 1.3 — берётся
     бинарь с релизов GitHub с проверкой SHA-256. `openssl` с `-provider legacy`. Версии утилит
     печатаются в логе теста.

- **D619. Результат спрятан, пока не нажат** (ответ на 264), на обеих платформах, как коды в 2FA.
  - Текст показан как `•••• 1 240 знаков · нажмите, чтобы показать`. Нажатие показывает, повторное —
    прячет.
  - Через минуту без касаний текст снова прячется. Сама минута простоя при этом не меняется: она
    опускает шторку (D598).
  - После шторки, фона и снятия замка текст снова спрятан.
  - «Копировать» и «Сохранить» работают и со спрятанным текстом.
  - Для двоичного файла прятать нечего: на экране только имя и размер.
  - Пароли и ключи во вводе — скрытые поля с «показать».

### Тесты приложения и порядок

- **D612. Тесты приложения** (пересмотрено в 0.4). `desktopTest`; камера — свой `QrScanner`, как в
  `TwoFaImportTest`; файл — `FakeFilePicker`; ключи — поддельный `SshKeyring`; сохранение —
  поддельный `FileSaver`.
  - Каждый способ: QR, несколько QR, файл → текст и → файл; текст «Сохранить файлом».
  - Ошибки каждого способа; подсказка о чужом формате; 64 КБ ± 1 → текст / файл.
  - **Ничего не сохраняется:** после закрытия (кнопкой, по простою без данных, «Закрыть» на
    шторке) storage приложения пуст, в снимке, журнале событий и логах нет ни входа, ни пароля, ни
    ключа, ни результата, ни настроек; массивы обнулены; повторное открытие — с умолчаниями.
  - **Замок** (Superizer `LockShellTest` и тест приложения):
    - вход по промокоду — без замка;
    - есть результат + простой → шторка, а не закрытие;
    - есть результат + фон → шторка;
    - повторный промокод при результате → шторка;
    - нет результата + простой → закрытие без замка;
    - отказ в замке → приложение не показывается;
    - нет блокировки экрана → закрытие и стирание.
  - `secureWindow` — в `SecureWindowTest` (Android instrumented), как у 2FA.
  - D619: после расшифровки текста нет в дереве семантики, пока не нажато; минута без касаний и
    возврат из-под шторки снова прячут; «Копировать» работает со спрятанным текстом.

  **Порядок:**
  1. Superizer: `LockPolicy.WhileHolding` + `holding()`, тесты, публикация.
  2. kit, этап A: AES-CBC/CTR/…, PBKDF2, `EVP_BytesToKey`, SHA-2, `OpensslEnc`; age X25519 +
     scrypt + SSH-ключи из файла; матрица D618 для этого объёма.
  3. `services/file-saver`.
  4. `apps/cr-restore`: выбор, split-qr, age, openssl; промокод, `.secrets/promo-codes.md`,
     `verify.sh`, скриншоты.
  5. kit, этап B: остальные шифры и дайджесты D609; ML-KEM-768 (D614). Каждое расширение
     матрицы — тем же тестом.

  Push в `main` выпускает альфу — только по слову владельца.
