# 01 — протокол: соединение, привязка, запрос пароля (D556–D561)

> 2026-10-25, при постройке (шаги 1–5). README §3–§4 говорит, что делать; здесь — байты. Всё, что
> README не определял, отмечено номером решения. Код — `unitool-kit/…/kit/link/` (общий для
> телефона и CLI), без ввода-вывода.

## 1. Соединение (D556)

Компьютер подключается к телефону по TCP (порт из mDNS, обычно 47370) и первым шлёт 4 байта:

```
55 4C 01 m        "UL", версия 1, m = 01 привязка (XXpsk3) | 02 сеанс (KK)
```

Дальше — только кадры: `uint16` длина (big-endian) ‖ сообщение Noise, не больше 65535 байт
(usb-sign D312). Пролог Noise — `"unitool-link/1"` ‖ эти 4 байта: подмена режима ломает рукопожатие.
Неизвестная преамбула, кадр длиннее предела, 10 с тишины в рукопожатии — телефон закрывает
соединение молча.

Внутри транспорта Noise — сообщения в SSH wire, первый байт — тип (§4).

## 2. Привязка (D557)

```
компьютер (инициатор)                           телефон (ответчик)
QR: unitool-pair:1:<b64url(C ‖ psk)>;name=laptop;ssh=<b64url(blob)>;addr=192.168.1.5,…
                                                скан → «Привязать laptop? SHA256:…» [Да]
                                                слушает, mDNS-имя  p<hex(SHA-256("unitool-pair" ‖ psk))[0..15]>
mDNS: ищет это имя
55 4C 01 01
→ e                                             
                                              ← e, ee, s, es
→ s, se, psk
                                                проверяет: s компьютера == C из QR, иначе закрыть
                                              ← WELCOME {имя телефона, linkId 8 байт}
запомнил P, имя, linkId
→ PAIRED
                                                запомнил C, ssh-ключ, имя, linkId
```

- **QR** — формат usb-sign (`unitool-pair:1:` + base64url без `=` от 64 байт + `;name=`), плюс
  `;ssh=` (blob открытого SSH-ключа, base64url) и `;addr=` (адреса компьютера через запятую,
  подсказка; в v1 телефон их не использует). Значения `name` — percent-encoding UTF-8, до 64 символов.
- `psk` живёт в памяти host 5 минут (README §3), на диск не пишется. Телефон срок не проверяет: без
  host этот `psk` никому не нужен.
- Телефон принимает QR, только если SSH-ключ — `ssh-ed25519` или `ssh-rsa` ≥ 2048 (D537).
- **mDNS-имя на время привязки** выводится из `psk`: сосед по сети его не угадает, а host знает,
  какое имя искать. Телефон с QR ещё ничего не знает о компьютере, кроме QR.
- `psk` проверен у телефона после третьего сообщения, у компьютера — только когда пришёл
  `WELCOME` (зашифрован ключом, в который вошёл `psk`). Телефон сохраняет компьютер по `PAIRED`,
  компьютер — перед отправкой `PAIRED`. Потерялся `PAIRED` — на компьютере лишняя запись, первый
  же запрос скажет «телефон не узнал компьютер, привяжите заново».

## 3. Сеанс: запрос пароля (D558)

```
компьютер                                       телефон
mDNS: ищет свои linkId                          объявляет по имени на каждый привязанный компьютер:
                                                  <hex(linkId)> (16 hex-знаков), TXT v=1
55 4C 01 02
→ e, es, ss   (пустой payload, но с тегом)      пробует ключ C каждого привязанного компьютера:
                                                  чей ключ открыл сообщение — тот и звонит.
                                                  Ни один — закрыть молча
                                              ← e, ee, se
→ PW_REQ
                                              ← PW_SHOWN        (лист на экране)
                                              ← PW_RES          (или ERROR)
закрыть
```

- В открытом виде компьютер себя не называет: что это за компьютер, телефон узнаёт перебором
  ключей (их единицы, одна проверка — три X25519).
- Один `linkId` на привязку, а не один на телефон: двум компьютерам не нужно знать общий
  идентификатор.

## 4. Сообщения (D559)

SSH wire (`kit.ssh.WireWriter`), первый байт — тип.

| Тип | Имя | Кто | Поля |
|---|---|---|---|
| 1 | `ERROR` | ↔ | `string code` |
| 10 | `WELCOME` | ← телефон | `string phoneName`, `string linkId` (8 байт) |
| 11 | `PAIRED` | компьютер → | — |
| 20 | `PW_REQ` | компьютер → | `uint32 v=1`, `string id` (16 байт), `string origin`, `string browser`, `uint64 iat` (мс эпохи) |
| 21 | `PW_SHOWN` | ← телефон | `string id` |
| 22 | `PW_RES` | ← телефон | `uint32 v=1`, `string id`, `string decision` (`fill`/`deny`/`timeout`), `string box` (age, пусто кроме `fill`) |

Коды `ERROR`: `clock` (часы расходятся > 5 мин), `replay` (повтор `id`), `busy` (на телефоне уже
открыт лист для другого компьютера), `version`, `origin` (не `http://` и не `https://`),
`locked` (список паролей не открыт — «Пароли» под замком).

`box` — age (бинарный, не armor) на SSH-ключ компьютера, внутри JSON одной строкой:

```json
{"req":"<hex SHA-256 байтов PW_REQ целиком, с типом>","origin":"https://github.com","username":"octocat","password":"…"}
```

Host принимает `PW_RES`, только если `id` — его запрос, а внутри `req` и `origin` совпали с
отправленным (README §4).

## 5. Порт расширения ↔ host (D560)

Native messaging: 4 байта длины (порядок байтов машины) + JSON UTF-8. Расширение держит
`connectNative` на время одной операции.

| Расширение → host | Host → расширение |
|---|---|
| `{"type":"fill","origin":…,"browser":…}` | `{"type":"state","state":"searching"}` → `"found"` → `"shown"`, затем `{"type":"fill","username":…,"password":…}` или `{"type":"done","decision":"deny"|"timeout"}` или `{"type":"error","code":…}` |
| `{"type":"pair","name"?:…}` | `{"type":"pair","uri":…,"svg":…,"fingerprint":…,"expires":…}`, затем `{"type":"paired","phone":…}` или `error` |
| `{"type":"devices"}` | `{"type":"devices","phones":[{"id","name","pairedAt","lastSeen"}],"key":{"path","fingerprint"}}` |
| `{"type":"forget","id":…}` | `{"type":"devices",…}` |
| `{"type":"cancel"}` | host закрывает соединение с телефоном и отвечает `done` |

Коды ошибок: `not-paired`, `no-phone` (не нашёл за 60 с), `phone-refused` (KK не сошёлся — телефон
забыл компьютер), `bad-response`, `key` (ключ SSH не читается или под фразой), `clock`, `busy`,
`locked`, `origin`, `internal`. Пароль в ответе host — единственное место, где он есть открытым
вне телефона, и живёт там до вставки (D535).

QR для попапа host рисует сам — SVG из `kit.qr`, — чтобы у расширения не было своей библиотеки QR.

## 6. Подбор записей по сайту (D561)

eTLD+1 — по снимку Public Suffix List (publicsuffix.org, разделы ICANN и PRIVATE) в «Паролях».
PRIVATE нужен: без него `a.github.io` и `b.github.io` — «один сайт». Снимок обновляется скриптом
`scripts/update-psl.sh`; дата снимка — в коде. Хост — IP-адрес или `localhost` → сравнение по
хосту целиком.
