# .ai-notes/passwords-browser — пароли с телефона в браузер компьютера по сети и по кабелю

## Что сказал владелец (близко к тексту)

> «Спланируй, как сделать, чтобы компьютер по USB или сети шарил пароль, зашифрованный ключом от SSH
> этого компьютера. То есть надо сделать расширение для браузера, которое подставляет пароли, но
> расшифровывает уже когда оно придёт. Делаем pair вначале и потом передаём внутри локальной сети
> зашифрованный пароль, каждый раз разрешая в интерфейсе и делая разлок. USB, если можно, тоже.»

Ответ на 0.1:
> «Все да, 235 пока не думаем.»

Как это прочитано:
- Пароли живут в «Паролях» на телефоне, как сейчас. На компьютере их нет: ни в расширении, ни на диске.
- «Зашифрованный ключом от SSH этого компьютера» значит, что телефон шифрует один пароль в age на
  открытый SSH-ключ компьютера (`ssh-ed25519` / `ssh-rsa`). Так же 2FA и «Пароли» уже шифруют
  экспорт, только получатель здесь — ключ компьютера, а не ключи GitHub. Расшифровывает компьютер в
  момент подстановки, закрытым ключом из `~/.ssh`.
- «Разрешая в интерфейсе и делая разлок» значит, что на каждый пароль телефон показывает запрос и
  спрашивает биометрию (`UserPresence.confirm`). Окна доверия нет.
- «Pair вначале» значит, что компьютер один раз привязывается к телефону по QR. Без привязки
  ни запрос, ни ответ не принимаются.

## Короткий ответ

1. **Четыре части** (D534):
   - **«Пароли» на телефоне** — страницы «Компьютеры» и «Запрос пароля»;
   - **`services/link`** — сокет в локальной сети и, позже, кабель на телефонах;
   - **CLI `unitool`, приложение `browser`** — native messaging host для браузера: привязка, связь с
     телефоном, расшифровка;
   - **расширение** `unitool-browser/` для Chrome и Firefox. Это то же расширение, что в плане
     `twofa-browser`: одно расширение, две функции (вопрос 233).
2. **Расширение само ничего не расшифровывает и не хранит** (D535). У браузера нет доступа к
   `~/.ssh` и к сокетам, поэтому всё это делает `unitool browser host`. Этот процесс браузер
   запускает сам через native messaging, он работает от имени пользователя. Расширение получает
   открытый пароль только на время подстановки и сразу передаёт его в поле.
3. **Два слоя шифрования, у каждого своя задача** (D536):
   - **канал — Noise `KK`** с ключами, которыми стороны обменялись при привязке. Это тот же канал, что
     в `usb-sign` (D310), код в `kit.link`. Он доказывает, что запрос пришёл с привязанного
     компьютера, а ответ — с привязанного телефона, и прячет от соседей по Wi-Fi, какой сайт
     запрошен;
   - **пароль — age на SSH-ключ компьютера**, как просил владелец. Даже внутри канала пароль
     открывается только в процессе, который держит закрытый ключ, и только в момент прихода.
4. **Звонит всегда компьютер, слушает телефон** (D538). Пока «Пароли» открыты на экране и есть
   привязанные компьютеры, телефон слушает порт в Wi-Fi и объявляет себя через mDNS. Компьютер
   подключается к нему только на время запроса. На компьютере не открывается ни одного входящего
   порта, а файрвол не мешает. По кабелю направление то же: usbmuxd к iPhone, AOA к Android
   (`usb-sign` D307).
5. **Запрос** (D541): расширение отправляет `origin` вкладки. Список паролей с телефона не уходит:
   подходящие записи по сайту выбирает телефон. Человек видит компьютер и сайт, выбирает запись,
   если их несколько, и подтверждает биометрией. Если сайт записи не совпадает с запрошенным,
   телефон показывает красное предупреждение о фишинге (D543).
6. **Ответ** (D542): `age(ключ компьютера, {req, origin, username, password})`. Host проверяет, что
   ответ относится к его запросу и к тому же сайту. Расширение вставляет логин и пароль только в
   ту вкладку, с которой был запрос, если она всё ещё на том же сайте. Форму оно не отправляет.
7. **Без сервера в v1** (D539). Пуш, который будит телефон, — следующий шаг через unitool-server.
   Пока человек сам открывает «Пароли» на телефоне, когда компьютер просит: «Откройте Пароли на
   телефоне».
8. **USB — да, но вторым этапом** (D548). Протокол тот же, меняется только труба. Для кабеля нужны
   разведки S1 (iPhone/usbmuxd) и S2 (Android/AOA) из `usb-sign`, их ещё не проводили. Сеть
   покрывает оба телефона с меньшим риском.
9. **Оценка** (D553): ≈ 18,5 рабочего дня на сеть (v1), +7 на кабель, +4 на пуш-будильник.

## 1. Схема

```
 браузер                  unitool browser host (CLI)            телефон · Unitool · «Пароли»
 ───────                  ──────────────────────────            ────────────────────────────
 ПРИВЯЗКА (один раз)
 попап «Привязать телефон» ─▶ ключ канала C (X25519, ~/.config/unitool/link/)
                              выбор SSH-ключа: ~/.ssh/id_ed25519
 QR в попапе ◀─────────────── unitool-pair:1:{C, ssh-pub, psk, имя «laptop»}
                                                                 «Компьютеры» → [Привязать] → скан QR
                                                                 «Привязать laptop? SHA256:ab…» [Да]
                                                                 слушает :47370, mDNS _unitool._tcp
                              ── Noise XXpsk3 (psk из QR) ──────▶ обмен ключами: C ↔ P
                              запомнил P, «Pixel 7»              запомнил C, ssh-pub, «laptop»

 ЗАПРОС
 клик по значку / Ctrl+Shift+L
 {origin: https://github.com} ─▶ «Откройте Пароли на телефоне» ◀─ человек открывает «Пароли»
                              mDNS → 192.168.1.20:47370          (телефон слушает, пока экран открыт)
                              ── Noise KK ──────────────────────▶
                              REQ{id, nonce, origin, browser}    лист: «laptop · Chrome просит пароль
                                                                 для github.com»
                                                                 записи с github.com: [octocat] [work]
                                                                 выбор → биометрия ✓
                              ◀── RES{id, age(ssh-pub, {req: sha256(REQ), origin, username, password})}
                              расшифровка ~/.ssh/id_ed25519
                              проверка req и origin
 {username, password} ◀────── (затёрто сразу после отправки)
 вкладка всё ещё github.com?
 → вставка в поля, без отправки формы
```

## 2. Почему так, а не проще

| Вариант | Почему нет |
|---|---|
| Только age, без канала (запрос открытым текстом, ответ — age) | соседи по Wi-Fi видят, какой сайт открывают; любой в сети может слать телефону запросы от имени компьютера; ответ телефона ничем не подписан. Noise закрывает всё это кодом, который нужен `usb-sign` в любом случае |
| Только канал, без age | безопасно, но владелец просил шифровать именно ключом компьютера. К тому же age даёт полезное свойство: открытый пароль есть только у процесса с закрытым ключом, а не у всего, через что идёт канал (демон `link`, когда он появится; журналы; отладка) |
| Расшифровка в расширении | у расширения нет доступа к `~/.ssh`. Копировать SSH-ключ в `storage.local` браузера хуже, чем держать его там, где он лежит |
| Расшифровка через ssh-agent | агент умеет только подписывать. Для age нужен сам закрытый скаляр, поэтому ключ из агента, `sk-*` и аппаратные ключи не подходят (D545) |
| Компьютер слушает, телефон звонит | на компьютере пришлось бы постоянно держать открытым порт в сети, а firewalld (Fedora) его закрывает. Телефон и так на экране в момент запроса, так что пусть слушает он |
| Через сервер | владелец сказал «внутри локальной сети». Сервер — только будильник, и только на следующем шаге (D550) |

## 3. Привязка (D537)

- **Где начинается:** в попапе расширения кнопка «Привязать телефон». Её дублирует команда
  `unitool browser pair`, она печатает QR в терминал.
- **Что host делает перед QR:**
  - заводит ключ канала `C`, если его ещё нет (`~/.config/unitool/link/key`, права `0600`);
  - выбирает SSH-ключ: первый из `id_ed25519`, `id_rsa`, другой можно указать через `--key`.
    ECDSA и `sk-*` age не поддерживает, их host отвергает с причиной.
- **Что в QR** — `unitool-pair:1:` (префикс из `usb-sign`, вопрос 165) и:
  - `C`;
  - открытый SSH-ключ целиком;
  - `psk` — 32 байта, живёт 5 минут;
  - имя компьютера;
  - адреса компьютера в сети, только как подсказка.
- **На телефоне:** «Пароли» → «Компьютеры» → «Привязать». Камера сканирует QR, телефон показывает
  «Привязать laptop?» и отпечаток SSH-ключа `SHA256:…`. Попап показывает тот же отпечаток.
- **Рукопожатие:** Noise `XXpsk3` с `psk` из QR. Подсунуть свой ключ вместо `C` или `P` без `psk`
  нельзя, поэтому сверять коды глазами не нужно, как и в `twofa-browser` D434.
- **Что хранят стороны:**
  - телефон — `C`, SSH-ключ, имя и дату в `runtime.secrets` «Паролей» (`KEY_COMPUTERS`);
  - компьютер — `P` и имя телефона в `~/.config/unitool/link/peers` (`0600`).
- **Сколько привязок:** один компьютер может привязать несколько телефонов, но запрос уходит
  первому найденному. Телефон может привязать несколько компьютеров.
- **Отвязать:** на телефоне «Забыть компьютер», на компьютере `unitool browser forget` или кнопка в
  попапе.

## 4. Протокол внутри канала (D540–D542)

Сообщения в SSH wire, как в `usb-sign` D312 (`kit.link`). Поверх `KK` — одна служба
`passwords` (если демон `link` появится, она станет одной из его служб, D343).

```
REQ  = { v:1, id: 16 байт, origin: "https://github.com", browser: "Chrome 141 · Linux", iat }
RES  = { v:1, id, decision: "fill" | "deny" | "timeout",
         box: age(ssh-pub компьютера, JSON{ req: hex(SHA-256(REQ)), origin, username, password }) }
```

- Телефон отвергает `REQ`, если `iat` отличается от его часов больше чем на ±5 мин или `id`
  повторяется. Один ожидающий запрос на компьютер; новый отменяет старый.
- Host принимает `RES`, только если `id` — его последний запрос, а внутри age `req` и `origin`
  совпадают с отправленным. Иначе отбрасывает молча и пишет «ответ не к этому запросу».
- Отказ (`deny`) не шифруется: его подделка ничего не даёт.
- Ожидание: компьютер ищет телефон до 60 с и показывает «Откройте Пароли на телефоне». Лист на
  телефоне живёт 60 с.

## 5. Телефон: «Пароли» (D543–D544)

- **Новые страницы:**
  - **«Компьютеры»**: список привязанных, «Привязать», «Забыть», «последний запрос: вчера, github.com»;
  - **лист «Запрос пароля»** поверх любой страницы «Паролей».
- **Слушает, только пока открыты «Пароли»**, есть хотя бы один привязанный компьютер и приложение
  на экране. Порт 47370 (тот же, что у `usb-sign`), mDNS `_unitool._tcp`. Имя в mDNS — случайный
  идентификатор привязки, а не «Pixel 7 Ивана». Соединение без `KK` от известного `C` сразу
  закрывается. Ушли с экрана или сработал idle-выход хоста (через минуту) — слушатель закрыт.
- **Лист:**
  - крупно сайт (IDN и в Unicode, и в `xn--`);
  - имя компьютера и браузера с пометкой «по словам компьютера»;
  - записи, у которых `Site.host()` совпадает с хостом запроса по eTLD+1;
  - одна запись — она уже выбрана, несколько — выбор, ни одной — поиск по всем;
  - запись, выбранная поиском, у которой сайт другой, — красное «Сайт записи — github.com, а
    просит github-login.example. Это может быть подделка»;
  - кнопки «Отправить» (биометрия, `UserPresence.confirm` — каждый раз) и «Отказать».
- **Журнал на карточке компьютера:** время, сайт, итог. Без логинов.
- **Заметка в ответ не попадает** — только логин и пароль.

## 6. Компьютер: CLI `unitool browser` (D545–D547)

- **Команды:**
  - `unitool browser install` — пишет манифесты native messaging для Chrome, Chromium, Brave, Edge
    (`~/.config/<браузер>/NativeMessagingHosts/cx.m42.unitool.json`) и Firefox
    (`~/.mozilla/native-messaging-hosts/`) с id нашего расширения в `allowed_origins`;
  - `pair`, `devices`, `forget`;
  - `host` — то, что запускает браузер (stdio, длина 4 байта + JSON).
- **Демона в v1 нет** (D546). Host живёт столько, сколько открыт порт расширения. Сокет к телефону он
  открывает на время одного запроса. Когда появится демон `unitool link run` (`usb-sign` D340),
  host будет ходить через `link.sock`, а кабелем будет владеть демон.
- **Расшифровка — в host** (D545). Он читает файл ключа OpenSSH: Ed25519 или RSA, `openssh-key-v1`,
  только без парольной фразы. Открывает age, отдаёт расширению
  `{username, password}` и затирает буферы. На диск и в журнал ничего не пишет.
- **Ключ с парольной фразой — не в v1** (ответ 235: «пока не думаем»). `pair` проверяет ключ
  сразу: если он под фразой, привязка не начинается, а host пишет «Ключ ~/.ssh/id_ed25519 защищён
  фразой — такие пока не поддерживаются; укажите другой: `--key`». Так человек узнаёт об этом при
  привязке, а не при первом запросе пароля.
- **Что придётся перенести в `:unitool-kit`:** `Age` (расшифровка ssh-ed25519 / ssh-rsa) и
  `OpenSshKeyFile` из `services/ssh` — так же, как раньше переносили `kit.crypto`. Сейчас у них
  нет цели `linuxX64`. Плюс новый `kit.link`: Noise и кадры, без ввода-вывода.
- **mDNS на Linux:** сам запрос по UDP multicast (`224.0.0.251:5353`) — полторы сотни строк, без
  avahi. Если ответа нет, host пробует последний известный адрес.
- **Платформы — платформы CLI**, сейчас Linux (`usb-sign` D326). macOS и Windows придут вместе с CLI.

## 7. Расширение (D549)

- **Где:** `unitool-browser/`, TypeScript, MV3, Chrome и Firefox — общее с `twofa-browser` (вопрос 233).
- **Права:** `nativeMessaging`, `activeTab`, `scripting`, `storage` (только настройки). Ни
  `<all_urls>`, ни контент-скриптов на всех сайтах, ни `externally_connectable`. Страница не может
  вызвать расширение сама.
- **Запуск:** клик по значку или `Ctrl+Shift+L`. Оба дают `activeTab` именно на эту вкладку.
- **Попап:**
  - «Ищу телефон… Откройте Пароли» и отсчёт;
  - затем «Вставлено: octocat» или «Отказано на телефоне»;
  - «Привязать телефон» с QR.
- **Вставка:**
  - только в вкладку запроса и только если её `origin` всё ещё равен `REQ.origin`;
  - верхний фрейм и фреймы того же `origin`;
  - поле пароля — видимое `input[type=password]`; логин — `autocomplete="username"/"email"`, иначе
    ближайшее текстовое поле перед паролем;
  - значение ставится через нативный setter плюс `input`/`change`, чтобы его видели React и Vue;
  - форма не отправляется.

  Поле не нашлось — кнопки «Копировать логин» и «Копировать пароль». Пароль из буфера стирается
  через 60 с, но только если расширение может это сделать, — честно сказать об этом в попапе.
- **Чего в расширении нет:** паролей в `storage`, ключей (ключи у host), `console.log` с
  данными. Открытый пароль живёт только в сервис-воркере до вставки.

## 8. Угрозы

| Кто | Может | Не может |
|---|---|---|
| Сосед по Wi-Fi | видеть, что телефон и компьютер общаются, и сколько байт; сорвать соединение | узнать сайт, логин, пароль; подсунуть запрос телефону или ответ компьютеру (Noise `KK`) |
| Фальшивый «телефон» в сети (объявил тот же mDNS) | принять соединение | пройти `KK`: не знает закрытый `P` |
| Вредоносная страница | ничего не знает о расширении | вызвать его: контент-скриптов и `externally_connectable` нет; вставка только по клику человека |
| Фишинговый сайт | попросить человека нажать на значок | остаться незамеченным: телефон показывает запрошенный сайт и не предлагает записи с другого сайта без красного предупреждения (D543) |
| Вредонос под тем же пользователем на компьютере | читать `~/.ssh` и ключ канала, слать запросы, читать вставленный пароль со страницы | получить пароль без человека: каждый запрос — лист и биометрия на телефоне. Это предел, как в `twofa-browser` и `sudo-approve`: против вредоноса с правами пользователя в момент ввода защиты нет и при ручном вводе |
| Укравший компьютер | то же, что вредонос | без телефона — ничего. На телефоне «Забыть компьютер» |
| Укравший телефон | — | `LockPolicy.Required` и биометрия на каждый пароль |
| Другое расширение в браузере | с правами на все сайты — прочитать пароль из поля после вставки (как и при ручном вводе) | вызвать наш host: в манифесте `allowed_origins` только наш id |
| Запись трафика сейчас, ключ потом (украли `~/.ssh` через год) | — | открыть старые ответы: age лежит внутри Noise с эфемерными ключами, записанный трафик без ключей сеанса не раскрыть |

## 9. USB (D548)

- **Протокол тот же**, меняется только труба (`usb-sign` 01):
  - **iPhone** — usbmuxd: host подключается к `127.0.0.1:47370` на телефоне через `/var/run/usbmuxd`
    (свой клиент usbmuxd). Это тот же слушатель, что в сети, только на loopback. Работает, пока
    «Пароли» на экране, — и в сети то же условие.
  - **Android** — AOA через usbfs: host переводит телефон в режим аксессуара, телефон открывает
    `UsbAccessory`. Пока телефон в этом режиме, файлы с компьютера не видны (`usb-sign` D307).
- **Порядок:** host пробует кабель, потом сеть.
- **Почему вторым этапом:**
  - кабель нужен только тем, у кого нет общей сети. Это гостевой Wi-Fi с изоляцией клиентов,
    корпоративные сети и Wi-Fi компьютера, выключенный ради безопасности;
  - разведки S1 и S2 из `usb-sign` не проводились. Если они не пройдут, в сети ничего не меняется.
- **Общий код:** код трубы потом станет частью демона `link`.

## 10. Решения

| № | Решение |
|---|---|
| D534 | Части: «Пароли» (страницы «Компьютеры», лист «Запрос пароля»), `services/link` (сеть, позже кабель), CLI `unitool browser` (native messaging host), расширение `unitool-browser/`. Superizer в v1 не меняется |
| D535 | Пароли хранит только телефон. Расширение не хранит ни паролей, ни ключей; host не пишет на диск ничего, кроме ключа канала и списка привязанных телефонов |
| D536 | Два слоя: канал Noise `KK` (`kit.link`, как `usb-sign` D310) + пароль в age на SSH-ключ компьютера (просьба владельца) |
| D537 | Привязка: QR из попапа или терминала `unitool-pair:1:{C, ssh-pub, psk 5 мин, имя, адреса}` → Noise `XXpsk3`; отпечаток SSH-ключа показывают обе стороны; ECDSA и `sk-*` отвергаются |
| D538 | Телефон слушает (порт 47370, mDNS `_unitool._tcp` со случайным именем), только пока «Пароли» на экране и есть привязки. Компьютер звонит на время запроса; входящих портов на компьютере нет |
| D539 | v1 без сервера: человек сам открывает «Пароли» по просьбе компьютера |
| D540 | Сообщения в SSH wire, служба `passwords`; один ожидающий запрос на компьютер; ±5 мин на часы; повтор `id` отвергается; ожидание 60 с с обеих сторон |
| D541 | В запросе только `origin`, браузер и время. Список записей с телефона не уходит; выбирает телефон |
| D542 | Ответ — age на SSH-ключ компьютера с `req = SHA-256(REQ)` и `origin` внутри; host проверяет оба; отказ не шифруется; заметка не отправляется |
| D543 | Подбор записей по eTLD+1 хоста; запись с другого сайта — только через поиск и с красным предупреждением; IDN показывается в двух видах |
| D544 | Каждый пароль — `UserPresence.confirm`; окна доверия нет; журнал на карточке компьютера без логинов |
| D545 | (1.0, ответ 235) Расшифровка — в `unitool browser host` файлом ключа OpenSSH (Ed25519, RSA, только без парольной фразы; ключ под фразой `pair` отвергает сразу). ssh-agent не годится: он не расшифровывает. `Age` и `OpenSshKeyFile` переезжают в `:unitool-kit` |
| D546 | Демона в v1 нет: host запускает браузер, сокет живёт один запрос. С демоном `link` — через `link.sock` |
| D547 | mDNS на компьютере — свой запрос по UDP multicast, без avahi; запасной путь — последний адрес |
| D548 | USB — второй этап, после разведок S1/S2 `usb-sign`: iPhone через usbmuxd к тому же слушателю, Android через AOA; сначала кабель, потом сеть |
| D549 | Расширение: `nativeMessaging`, `activeTab`, `scripting`, `storage`; клик или `Ctrl+Shift+L`; вставка только во вкладку запроса с тем же `origin`, без отправки формы; иначе «Копировать» |
| D550 | Пуш-будильник — следующий шаг через unitool-server: пуш «laptop просит пароль» без сайта, нажатие открывает «Пароли», дальше всё по сети. Нужен адрес приложения `pa_` (`twofa-browser` D445) |
| D551 | iOS: `NSLocalNetworkUsageDescription` и `NSBonjourServices = _unitool._tcp` в Info.plist. Разрешение «Локальная сеть» спрашивается при первой привязке, а не при установке |
| D552 | Android: `NsdManager` и `MulticastLock` только на время экрана; новых разрешений, кроме `CHANGE_WIFI_MULTICAST_STATE` (normal), нет |
| D553 | Оценка: сеть v1 ≈ 18,5 дня; USB +7 (включая 2 дня разведки); пуш +4 |

## 12. Риски

- **Firefox из snap (Ubuntu по умолчанию) и Chrome из Flatpak.** Native messaging в snap-Firefox
  работает через портал (Firefox 106+), во Flatpak-Chrome без обёрток не работает. Это надо
  проверить в первый день.
- **Сети с изоляцией клиентов** (гостевой Wi-Fi, часть роутеров с «AP isolation») и VPN на телефоне —
  mDNS и соединение не проходят. Ответ на это — кабель (D548) или, позже, сервер-труба
  (`usb-sign` вопрос 167).
- **iOS режет multicast** без `NSBonjourServices`, а без разрешения «Локальная сеть» молча не
  соединяет. Попап должен говорить «Разрешите Unitool доступ к локальной сети», а не просто
  «телефон не найден».
- **Публикация расширения** в Chrome Web Store и AMO — тот же вопрос, что `twofa-browser` 197.

## 13. Вопросы владельцу

| № | Вопрос | Рекомендация / ответ |

| 233 | Одно расширение на 2FA-коды (`twofa-browser`) и пароли или два разных? | **Ответ:** да → одно: привязка и попап общие, человеку ставить одно. | 234 | Шифрование канала Noise поверх age (D536) — устраивает, или нужно строго «только SSH-ключ»? | **Ответ:** да → Noise нужен: без него соседи по сети видят сайт и могут слать телефону запросы, а ответ телефона ничем не подписан. Ключ SSH остаётся тем, чем открывается пароль |
