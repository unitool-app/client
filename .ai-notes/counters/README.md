# .ai-notes/counters — мини-приложение «Счётчики»: табло с именованными счётчиками

> **Версия:** 0.1 · **Статус:** предложение, ждёт владельца · **Дата:** 2026-10-18
>
> Сквозная нумерация: решения D516–D527, вопросы 228–232.

## Что сказал владелец (близко к тексту)

> «Сделай мини-приложение со счётчиками: заводим новый счёт, называем его, и там заводим сколько-то
> счётчиков, каждый со своим именем. Например, для игры, где у каждого есть уровень, и их надо считать.»

## Как это выглядит

**Список табло** (первый экран):

```
┌ Счётчики ──────────────────────┐
│ Манчкин, пятница        4 · 2 ч│
│ Подходы в зале          3 · вчера│
│ Кофе за неделю          1 · 5 дн│
│                                │
│                     [＋ Новое] │
└────────────────────────────────┘
```

Строка — имя табло, сколько в нём счётчиков, когда менялось. Тап — открыть. Долгое нажатие —
переименовать / дублировать / удалить.

**«Новое табло»**: имя («Манчкин, пятница»), затем сразу список имён счётчиков (поле + «Добавить»:
«Аня», «Боря», «Вика»). Начальное значение по умолчанию 0 (или 1 — шаблон «Игра с уровнями», см. D522).

**Табло** (главный экран):

```
┌ ← Манчкин, пятница        ⋮ ┐
│ Аня              [−]   7  [+]│
│ Боря             [−]   5  [+]│
│ Вика             [−]  10  [+]│  ← достиг максимума — подсвечен
│ [＋ Счётчик]                 │
└──────────────────────────────┘
  «Боря: 6 → 5»  [Отменить]       ← снэкбар после каждого изменения
```

- Крупные кнопки −/+ — главный жест, играют одной рукой за столом.
- Тап по числу — ввести значение вручную (или «+15» / «−3» как приращение).
- Долгое нажатие на строку — переименовать, удалить, сдвинуть вверх/вниз.
- Меню ⋮: «Сортировать по значению» (вкл/выкл), «Сбросить все», «Шаг», «Мин/макс», «История».

## Решения

- **D516.** Новое публичное офлайн-приложение `apps/counters`, AppId `counters`, пакет
  `cx.m42.apps.counters`, `CountersApp`. В каталоге, не на первом Home. Сеть, секреты, push — нет.
- **D517.** Две сущности: **табло** (`Board`: id, имя, счётчики, настройки, даты) и **счётчик**
  (`Counter`: id, имя, значение `Long`). Слово «счёт» в интерфейсе не используем — путается со
  счётом в банке; верхний уровень называется «табло».
- **D518.** Всё хранится в `runtime.storage` одним JSON (`storage.setJson("boards", …)`), как кэш
  курсов в converter. Объёмы крошечные, отдельная БД не нужна. Запись — сразу после каждого
  изменения (с дебаунсом ~300 мс при частых тапах).
- **D519.** Настройки табло: шаг (по умолчанию 1), начальное значение (для «Сбросить все»),
  необязательные мин/макс. Значение не выходит за мин/макс; достигший максимума подсвечивается
  (в Манчкине — победа на 10-м уровне).
- **D520.** Отмена: каждое изменение показывает снэкбар «Боря: 6 → 5 · Отменить». История — последние
  100 изменений табло (кто, было → стало, время), экран «История» в меню. Хранится вместе с табло.
- **D521.** Сортировка по значению — переключатель, по умолчанию выкл (порядок добавления, чтобы
  строки не прыгали под пальцем). При вкл — пересортировка с короткой анимацией.
- **D522.** Шаблоны при создании: «Пустое», «Игра с уровнями» (старт 1, мин 1, макс 10). Шаблоны
  только заполняют настройки, отдельной логики нет.
- **D523.** Экран не гаснет, пока открыто табло (переключатель в меню, по умолчанию вкл) — если у
  Superizer есть такой сервис; иначе пропускаем (вопрос 231).
- **D524.** Конфиг приложения (`CountersConfig`) пустой в 1.0; ссылка-активация с готовым табло — не
  делаем.
- **D525.** Логика (изменение, мин/макс, отмена, история, сортировка) — чистый Kotlin в
  `Boards.kt`, тесты в desktopTest без экрана; экран — `CountersScreen.kt`. Строки ru/en в
  `CountersStrings.kt`, как в date-diff.
- **D526.** Скриншот для стора — в `Screenshots.kt` (табло «Манчкин» с тремя игроками); приложение в
  `scripts/verify.sh`.
- **D527.** Иконка — табло с плюсом и минусом (Material-подобный path).

## Вопросы владельцу

- **228.** Один счётчик на строку — или у каждого участника **несколько чисел** (например, «уровень» и
  «сила» / «уровень» и «HP»)? Если да — табло получает колонки: имена колонок задаются при создании,
  строка = участник, в каждой ячейке свои −/+. Это заметно сложнее экрана (≈ +1 день). Предлагаю:
  1.0 — один счётчик, колонки — 1.1.
- **229.** Нужна ли история (D520) в 1.0, или хватит одной отмены последнего действия?
- **230.** Мин/макс и шаблон «Игра с уровнями» — оставить или убрать для простоты?
- **231.** «Не гасить экран» — делать (может потребовать сервис в Superizer, тогда новая версия
  библиотеки) или нет?
- **232.** Нужна ли отправка итогов («Поделиться» текстом: «Аня 7, Боря 5, Вика 10»)?

## Объём

Без колонок: ≈ 1 день (как date-diff). С колонками (вопрос 228): ≈ 2 дня.
