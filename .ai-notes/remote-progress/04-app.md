# 04 — Мини-апп «Прогресс» и правки Unitool

> Часть задания [remote-progress](README.md). Протокол — [01](01-model-and-protocol.md). Экраны
> развивают 08 §13: там подробные макеты детали и провала, здесь они не повторяются. Нового здесь
> три вещи: вкладка «Уведомления», «Настройки» с заглушкой и пейринг.

## 1. Где что лежит

| Что | Где | Почему там |
|---|---|---|
| мини-апп | `apps/progress` (`cx.m42.apps.progress`), AppId `progress` | обычный кирпич, как `apps/twofa` (D194) |
| контракт «адрес устройства» | `services/push-address`, commonMain | по образцу `services/qr-scanner` (D209) |
| реализация адреса | `composeApp`: `HostPushAddress` читает публичный `PushTransport.token` | только `composeApp` видит `superizer:host` |
| каналы, номер уведомления | `composeApp/src/androidMain/…/AndroidNotifier.kt` | Unitool рисует уведомления (13 §1) |
| iOS: показ в открытом приложении | `iosApp/iosApp/iOSApp.swift`, `willPresent` | Swift-сторона уведомлений |
| регистрация | `UnitoolHost.kt`: `register(ProgressApp())`, `service(PushAddress.Key, …)` | D1 |

**Superizer не меняется.** Нужен контракт 3 (`runtime.secrets`), то есть Superizer 0.4.0: работа
начинается от ветки, где он уже есть (00-TASK §3).

## 2. Манифест и зависимости

```kotlin
override val manifest = AppManifest(
    id = AppId("progress"),
    version = "1.0.0",
    minHostContract = 3,                       // runtime.secrets — секрет устройства
    metadata = AppMetadata(
        title = localized("ru" to "Прогресс", "en" to "Progress"),
        description = localized(
            "ru" to "Ход долгих задач с компьютера и уведомления от них",
            "en" to "Long-running jobs from your computer, and their notifications",
        ),
        icon = AppIcon.Path("…"),               // полоса с точками-шагами; нарисовать в 24×24
        category = "Инструменты",
    ),
    deepLinks = setOf("pair", "task", "notice"),
    // Замок по желанию (D236). Он же делает ссылки чувствительными: тикет из `pair?t=` не
    // попадает в журнал хоста, когда ссылку пришлось отбросить (D134).
    protection = AppProtection(lock = LockPolicy.OptionalOff),
)
```

- В каталоге, не на Home (D48).
- `requires` пуст. `PushAddress` и `QrScanner` необязательны: без них приложение работает опросом
  (desktop) и без кнопки «Сканировать» (подключение — ссылкой из камеры телефона).
- Зависимости модуля — как у `apps/twofa`: `superizer-core`, `ui`, `ui-theme`, `compose-unstyled`,
  `kotlinx-serialization-json`, `:services:qr-scanner`, `:services:push-address`. Плюс
  `kotlinx-datetime` — новая строка в каталоге версий: часы и минуты в поясе телефона.
- `explicitApi()`. Правило зависимостей (`checkDependencyRules`) — без исключений.

## 3. Контракт `services/push-address`

```kotlin
/** Where the server can reach this installation: the FCM registration, and what to call it. */
public interface PushAddress {
    /** Null while there is none: no Firebase in this build, not yet issued, or a desktop. */
    public val current: StateFlow<Address?>

    /** "Pixel 7", "iPhone" — the default name the phone offers; the person can change it. */
    public val deviceName: String

    public data class Address(val token: String, val platform: String)

    public companion object {
        public val Key: ServiceKey<PushAddress> = ServiceKey("push-address")
    }
}
```

`HostPushAddress` в `composeApp` получает `current` из `PushTransport.token` через `map`.
`deviceName` передаёт точка входа:
- Android — `Settings.Global.DEVICE_NAME`, если оно есть, иначе `Build.MODEL`;
- iOS — `UIDevice.current.model` («iPhone»): настоящее имя без особого entitlement iOS 16+ не отдаёт;
- desktop — имя хоста.

Это сознательный узкий отход от 13 §3 «токена в контракте нет» (D209): приложению, чья работа —
быть адресатом, адрес нужен.

## 4. Данные на телефоне

| Что | Где | Ключ |
|---|---|---|
| сервер и `deviceId` | `runtime.storage` | `identity` → `{server, deviceId}` |
| `deviceSecret` | **`runtime.secrets`** — сейф хоста | `device-secret` |
| курсор, время последней синхронизации и её успех | `runtime.storage` | `sync` → `{cursor, at, ok}` |
| задания — полная форма, до 200: идущие все, прошлые — последние | `runtime.storage` | `progress` |
| лента — до 500 | `runtime.storage` | `inbox` |
| устройство, CLI | `runtime.storage` | `device`, `clients` |
| прочитанное, не дошедшее до сервера | `runtime.storage` | `pending-reads` |

Журнал и хвост лога не хранятся: деталь берёт их с сервера при открытии (08 §13.5). Тест проверяет,
что в `runtime.storage` нет ни одной строки `ds_`.

## 5. Как приложение работает

### 5.1. `setup()` — пока жив процесс, даже без открытого экрана

```kotlin
override fun setup(ctx: AppSetupContext) {
    ctx.deepLink("pair")   { p -> config(ProgressConfig(pair = PairLink.parse(p))) }
    ctx.deepLink("task")   { p -> config(ProgressConfig(openTask = p["id"])) }
    ctx.deepLink("notice") { p -> config(ProgressConfig(openNotice = p["id"])) }
    val engine = ProgressEngine.of(ctx.runtime)                 // один на процесс
    ctx.runtime.scope.launch { ctx.runtime.push.messages.collect(engine::onPush) }
    ctx.runtime.scope.launch { engine.onStart() }               // PUT /devices/me + sync, если есть identity
}
```

`ProgressEngine` держит `StateFlow<ProgressState>` из хранилища и делает всю сеть. Экраны только
читают его и вызывают действия.

### 5.2. Синхронизация (D230)

Когда:
- при старте процесса;
- при открытии экрана;
- по приходу пуша — с задержкой 1 с, несколько пушей подряд дают одну синхронизацию;
- раз в 10 с, пока экран открыт (`onForeground`/`onBackground` инстанса, D204);
- по кнопке «Проверить сейчас».

Что:
1. `GET /v1/me/sync?cursor=…`. Если `more`, сразу следующая страница.
2. Применить: задания по `id` (новее по `rev`), ленту, `removed`, `device`, `clients`. Урезать до
   200 и 500.
3. Записать `sync = {cursor, at: serverNow, ok: true}`.
4. Ошибка сети → `ok: false`. От этого зависит `unverified` (01 §3.2).
5. Перед запросом дослать `pending-reads`.

### 5.3. Пуш в живой процесс

`onPush(message)`:
- `data.v == 1` и есть `id` → компактная форма (01 §4.2). Если `rev` больше, чем в кэше, обновить
  строку списка сразу, а полную форму взять синхронизацией.
- `noticeId` или `inboxId` → синхронизация.
- Неизвестное или битое → в журнал приложения, без падения.

Уведомление в шторке рисует не приложение (D27): в фоне — система по `notification`-блоку, на экране —
хост (`AndroidNotifier`) для итогов. Ход приходит с `silent=true` (01 §8.3).

### 5.4. Регистрация устройства и пуш-токен

- Устройство регистрируется **при первом пейринге**: адрес сервера приходит только из QR (D235).
- При каждом `onStart` и при каждом изменении `PushAddress.current` — `PUT /v1/devices/me` с
  токеном, именем, `locale` (язык хоста), `timeZone` (`TimeZone.currentSystemDefault().id`) и
  версией приложения.

  Это закрывает ротацию токена: сервер забывает протухший токен после ответа `UNREGISTERED` (02
  §5.2) и получает новый отсюда.
- Разрешение на уведомления запрашивается после первого успешного подключения:
  `runtime.push.requestPermission()`, диалог Android 13+ или iOS. Отказ приложение не ломает:
  «Настройки» покажут «Уведомления выключены в системе» и кнопку, которая спросит ещё раз.

### 6.2. Деталь задания

Макеты «идёт» и «упало» — 08 §13.2 без изменений:
- шаги со временем начала и длительностью;
- полоса счётчика под текущим шагом;
- блок «Что произошло»: сообщение, команда, код выхода, хвост лога моноширинным шрифтом с
  прокруткой и кнопкой «Копировать» через `LocalClipboardManager`;
- журнал.

Тексты причин — таблица 08 §13.2 без `limit`. «Событие после закрытия» — отдельной строкой под
причиной.

Отличия от 08:
- кнопки «Отменить» нет (вопрос 99);
- «Скрыть» — `POST …/hide`, задание уходит из списка на этом телефоне;
- без сети — то, что есть в кэше, и строка «Журнал и лог будут доступны при подключении».

Открывается тапом по карточке, тапом по пушу (`task?id=`) и тапом по записи ленты.

**Заглушка (D228):**
- Кнопка → `PUT /v1/me/mute {durationS}` с 3600, 18000, 36000 или 604800 → `mutedUntil` с сервера.
  Время «до 22:40» считается в поясе телефона.
- Нет сети → «Нет связи — не удалось заглушить. Попробуйте ещё раз». Состояние не меняется: правда
  у сервера, и приложение не притворяется, что заглушило.
- «Включить» → `{off: true}`.
- Когда `mutedUntil` прошло, баннер и строка исчезают сами по тикающим часам, без запроса.
- Баннер из §6.1 — та же кнопка «Включить».
- Ничего не делается с уже висящими в шторке уведомлениями: приложение их не рисовало (D27).

**Компьютеры:** «Отключить» — подтверждение «Отключить „ноутбук“? Он больше не сможет присылать
сюда уведомления» → `DELETE /v1/me/clients/{id}`.

**Это устройство:**
- «Изменить» имя → `PUT /v1/devices/me`.
- «Пуши»: `работают` · `недоступны в этой сборке` (нет Firebase / desktop) · `токен недействителен —
  перезапустите Unitool`.
- «Забыть это устройство» — подтверждение → `DELETE /v1/devices/me`. Потом стереть `identity`,
  `device-secret` и кэш. После этого экран пустой, как при первом запуске.

### 6.5. Подключение

1. «Сканировать QR» → `QrScanner.scan()`. Или ссылка `unitool://app/progress/pair?s=…&t=…` пришла
   системной камерой: открывается тот же экран с уже разобранной ссылкой.
2. Разбор `PairLink`:
   - нет `s` или `t` → «Это не код подключения»;
   - `s` не `https` → отказ, кроме отладочной сборки (`HostInfo.debug`): там `http` разрешён для
     эмулятора и локальной сети.
3. Уже есть `identity` с **другим** сервером → «Этот код от другого сервера (host). Переключиться?
   Подключения к текущему будут забыты» (D235). Согласие → «Забыть устройство» на старом сервере,
   если он отвечает, и дальше как в первый раз.
4. Нет `identity` → `POST /v1/devices`: секрет рождается здесь и кладётся в `runtime.secrets`.
5. `POST /v1/pairings/preview` → лист:

```
┌──────────────────────────────────────────────┐
│ Подключить «ноутбук»?                        │
│ Он сможет присылать на этот телефон          │
│ уведомления и ход задач.                     │
│                                              │
│ Сервер: progress.example.com                 │
│               [Отмена]   [Подключить]        │
└──────────────────────────────────────────────┘
```

6. «Подключить» → `POST /v1/pairings/claim`. Потом «Готово. В терминале появится ✓ Pixel 7». Потом
   запрос разрешения на уведомления (§5.4) и синхронизация.
7. Ошибки:
   - `410` → «Код истёк или закрыт — запустите `unitool-progress pair` ещё раз»;
   - сеть → «Нет связи с сервером» и «Повторить».

## 7. Правки Unitool вне мини-аппа

### 7.1. Сборка и регистрация

- `settings.gradle.kts`: `include(":apps:progress")`, `include(":services:push-address")`.
- `composeApp/build.gradle.kts`: зависимости на оба модуля.
- `UnitoolHost.kt`: `register(ProgressApp())` рядом с 2FA. `HostTools` получает `pushAddress`, и
  `buildHost` регистрирует его как сервис.
- `ExtensibilityTest` и другие тесты, считающие приложения, обновляются осознанно.

### 7.2. Android

- **Каналы.** `AndroidNotifier.ensureChannels()` вызывается из `MainActivity.host()` при построении
  хоста, а не при первом уведомлении: канал должен существовать **до** первого пуша, который
  нарисует Firebase (08 §9.3).

  | id | Название (ru / en) | Важность |
  |---|---|---|
  | `unitool.general` | как сейчас | `DEFAULT` |
  | `unitool.progress` | «Ход задач» / «Job progress» | `LOW`: без звука и всплывания |
  | `unitool.results` | «Итоги и уведомления задач» / «Job results and notices» | `DEFAULT` |

- **Номер уведомления** в `AndroidNotifier` — `0` вместо `1`, как у уведомлений, которые рисует
  Firebase. Тогда `tag + id` совпадают, и итог, нарисованный хостом на открытом экране, **заменяет**
  уведомление хода, нарисованное Firebase в фоне. Проверить на устройстве (05 §5): номер у Firebase —
  наблюдение, а не документированный контракт.
- **Отладочная сеть.** `src/androidDebug/res/xml/network_security_config.xml` разрешает `http` к
  `10.0.2.2`, `localhost` и адресам из `debugHosts` в `local.properties`. Подключается через
  `android:networkSecurityConfig` **только** в debug-манифесте. В release `http` запрещён, как
  сейчас.

### 7.3. iOS

`willPresent` в `iOSApp.swift` для пушей мини-аппа `progress`:

```swift
let content = notification.request.content
if content.userInfo["appId"] as? String == "progress" {
    // Shown by the system already; the app only needs the data, never a second banner.
    var data = strings(content.userInfo)
    data["silent"] = "true"
    UnitoolIos.shared.deliverMessage(data: data)
    completionHandler(content.interruptionLevel == .passive ? [.list] : [.banner, .list, .sound])
    return
}
completionHandler([.banner, .list, .sound])
```

- **Ход (`passive`)** в открытом приложении не всплывает баннером. Он молча ложится в центр
  уведомлений и заменяет прошлый по `apns-collapse-id`. Строка списка обновляется данными.
- **Итог** всплывает как обычно.
- Тап идёт прежней дорогой `didReceive` → `deliverTap` и работает без правок.
- Убитое приложение: уведомление рисует система. Тап запускает приложение и отдаёт данные через
  `launchOptions` — это уже есть.

## 9. Фикстуры в Unitool

`scripts/sync-progress-fixtures.sh <путь к unitool-progress>` копирует
`protocol/fixtures/` в `apps/progress/src/desktopTest/resources/fixtures/` вместе с `VERSION` и
`SHA256SUMS`. `FixturesTest` сверяет сумму. Копия в репозитории нужна, чтобы CI Unitool не зависел от
соседнего репозитория. Правка протокола, таким образом, — это два коммита в двух репозиториях, и
тест не даст забыть второй.
