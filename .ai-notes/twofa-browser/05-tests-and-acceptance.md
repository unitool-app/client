## 2. e2e: `unitool-browser/e2e`

### 2.1. Стенд

- **Сервер** — локальный unitool-server на SQLite, `PUSH_PROVIDER=log`, `TRUST_PROXY=loopback`,
  свободный порт. Тест поднимает и гасит его сам.
- **Браузер** — Playwright, Chromium, `launchPersistentContext` с `--load-extension=dist/chrome`.
  Адрес сервера подставляется сборкой `npm run build -- --server=http://127.0.0.1:<port>` (только
  для e2e; в обычной сборке `http:` запрещён).
- **Сайт** — локальная страница `http://localhost:<port>/login` с полем
  `autocomplete="one-time-code"`, проверяет код по известному секрету.
- **Телефон** — `phone-sim`: маленькая JVM-программа на `kit.otplink` (модуль Gradle
  `:unitool-browser:phone-sim`). Она регистрирует устройство (`POST /devices`, `apps: ["2fa"]`),
  заводит адрес, говорит с тестом через stdin/stdout JSON: `claim <uri>`, `inbox`,
  `approve <id> <n> <secret>`, `deny <id>`, `unlink <id>`. Так e2e проверяет живую совместимость
  TypeScript и Kotlin, а не только фикстуры.
- **mitm** — прокси между расширением и сервером, умеет подменить `phonePub`, повторить старый
  ответ, задержать.
- QR из попапа читается не камерой: тест берёт ссылку из DOM попапа (`data-link`).

### 2.2. Сценарии

| # | Что | Ожидание |

Firefox в e2e не входит: Playwright не ставит в него расширения. Firefox — ручной сценарий M11.

## 3. Ручной сценарий

Три прохода:
- **A** — эмулятор `unitool35` (камера `-camera-back imagefile:` с QR из попапа) + Chrome на этой машине,
  локальный сервер, `PUSH_PROVIDER=log`, входящие вместо пуша;
- **B** — Android-телефон + Chrome и Firefox, сервер `unitool.m42.cx`, настоящие пуши;
- **C** — iPhone (TestFlight) + Chrome.

| # | Шаг | Ожидание |
|---|---|---|
| M1 | поставить расширение из папки | права — только «unitool.m42.cx» |
| M2 | открыть 2FA впервые после обновления | вопроса о пушах **нет** (D446, если 193 = а) |
| M3 | привязать: «Браузеры → Привязать», камера | системный вопрос о пушах, затем «Готово» на обоих экранах |
| M4 | запрос на настоящем сайте с 2FA владельца (GitHub) | пуш с именем браузера и IP; число; аккаунт; биометрия; вход выполнен |
| M5 | экран заблокирован | в уведомлении нет сайта, числа, кода |
| M6 | 2FA выгружена, тап по пушу | экран запроса после замка (холодный старт) |
| M7 | не то число | отказ и предложение отвязать |
| M8 | телефон в авиарежиме | «Телефон не ответил» через 2 мин |
| M9 | отвязать с телефона, потом с браузера | обе стороны это видят |
| M10 | похожий сайт (своя страница на другом домене) | жёлтое «вы ещё не отправляли коды этому сайту» |
| M11 | Firefox | M1, M3, M4 |
| M12 | телефон в той же Wi-Fi и через LTE | «та же сеть» / «другая сеть» |
| M13 | только iOS: пуш при закрытом приложении, Face ID на «Отправить код» | как M4–M6 |

## 4. Критерии приёмки

1. Все проверки §1 зелёные.
2. E1–E18 проходят.
3. Проход A — без ✗; B и C — после выкладки сервера и Superizer (§5).
4. Протокол существует в двух реализациях (TypeScript в расширении и `kit.otplink`), обе проходят одни
   фикстуры. Третьей копии нет: 2FA и phone-sim импортируют `kit.otplink`.
5. Секрет TOTP не уходит с телефона ни в одном пути: тест `TwoFaPrivacyTest` и просмотр кода
   `BrowserLinks` (единственное, что читает аккаунт, — `Totp.code`).
6. Скриншоты 04 §3.8 приняты владельцем.
